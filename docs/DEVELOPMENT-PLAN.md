# 开源站群导航系统开发方案

更新日期：2026-10-18。状态：P0–P2 已完成，P3 代码与本地验收完成但真实 GitHub/Google 登录联调待凭据；P4 GitHub 项目模块已完成，开发、Review 与验收见 [P4 交付](history/P4-FINAL.md)。

本项目面向个人和小团队，以一套应用管理多个独立品牌导航站。共享资源，各站独立发布和运营；支持后台与文件编辑、独立或共享账号，以及人工或 AI 编写的模板。选择性复用既有经验与合适代码，既有生产系统长期保持原样。

本文负责交付范围和阶段。专题协议以[文档索引](README.md)链接的设计文档为准。正式品牌已确定为 Qoo.IM Directory（域名/仓库名待定），用户已在 P5 选择 AGPL-3.0（声明为 AGPL-3.0-only）；首个垂直模块已由用户确认为开源项目目录（GitHub 来源）。

## Review 后的范围调整

保留用户确认的产品能力，通过减少自动化和扩展数量控制首版规模。

| 能力 | 内部原型 | 首个公开版本 | 后续增强 |
| --- | --- | --- | --- |
| 站群与内容 | 三域名、资源与发布记录 | 建站、分类、多语言、搜索、审核、收藏 | 更多运营功能 |
| 配置双向编辑 | 快照与冲突原型 | 后台编辑、文件导出校验导入、冲突处理、预览发布回滚 | 自动三方合并 |
| 账号 | 独立与共享模式原型 | 可选账号空间、跨域免重复输入凭据、退出 | 公开页面自动探测、已有账号迁移工具 |
| 模板 | 一个最小模板 | 一个完整模板、扩展接口、AI 编写示例 | 更多模板及高级编辑 |
| 模块 | 验证注册边界 | 通用导航加一个确认后的垂直模块 | 更多垂直模块 |
| AI | 辅助编写源码 | 模板开发说明、夹具、验证工具 | 产品内生成翻译、审核和预算流水线 |

内部原型不是首个公开版本。首版保留双向配置与共享账号，延后自动化程度；AI 编写模板是正式路径，不要求首版内置 AI 生成器。

首版不包含建站 SaaS 计费、每站独立部署、运行时安装任意服务器代码或复杂拖拽搭建器。未知模块和不兼容模板不能通过配置发布。

## 架构与内容模型

采用模块化单体：一套应用、共享 PostgreSQL、多域名；后台和账号中心也由同一应用承载。P0 已锁定 Next.js、React、TypeScript、pg 与 Better Auth 版本，使用显式 SQL 验证事务和约束；版本见锁文件及依赖清单。Drizzle 未引入验证，不作为已选定依赖。认证适配基线见 [ADR-001](ADR-001-AUTH.md)。

Docker 部署，默认不依赖 Valkey。后台任务可由同一镜像的独立执行进程运行，数据库管理租约与状态，不依赖页面响应后未受管理的后台 Promise。

| 概念 | 职责 |
| --- | --- |
| 站点 | 域名、品牌、语言、导航、SEO、模块和模板 |
| 资源主档 | 基础事实、来源、公共翻译与类型扩展 |
| 站点发布记录 | 状态、分类、排序、文案和 SEO 覆盖 |
| 账号空间 | 身份隔离或共享边界，账号中心位置 |
| 模板 | 布局、视觉、交互和区块参数 |
| 模块 | 类型扩展、采集器、页面和后台功能 |

这些是正式产品设计概念；P0 已实现用于验证的部分表与接口，不能视为完整产品模型。资源可以发布到多个站，各站分类、文案和状态独立。人工覆盖字段不被采集覆盖；首版发布固定内容版本，主档变化生成待更新差异，经站点发布操作后生效，避免一次采集直接改变所有线上页面。

收藏、投稿和统计按站记录。可见性诊断解释未分发、未发布、译文不足等原因。公开查询、预览和管理查询的权限边界见 [公共数据访问](DATA-ACCESS.md)。

## 关键流程

1. 建站：选择模板和模块，配置品牌、语言、账号模式，绑定域名，预览后发布。
2. 内容运营：录入或导入主档，选择目标站点，编辑覆盖字段，审核发布。
3. 配置协作：后台或文件编辑完整快照，比较差异，拒绝过期版本，预览发布。
4. 页面定制：通过模板接口编写，维护者审查、测试、构建并部署。
5. 运行维护：查看任务失败、发布传播、诊断和备份恢复结果。

配置与身份细节分别见 [配置协议](CONFIGURATION.md)、[账号设计](IDENTITY.md)。

## 模板与垂直模块

模板接口提供站点上下文、主题、过滤后的公共数据、语言链接、分页、SEO 和交互组件；包含参数 Schema、兼容版本、夹具和 AI 开发说明。首版验收实际用 AI 编写一个模板，通过公开接口接入而不修改核心代码。

新增及实质修改的模板上线前由维护者审查，AI 生成源码同样适用。CI 检查模板对数据库、环境变量和认证内部模块的直接及间接依赖。这些限制防止误用，不是安全沙箱。

模块通过源码注册，声明页面、后台入口、任务与扩展数据。停用后入口和任务一致关闭，数据保留；删除另行操作。

首个垂直模块已确认为开源项目目录，P4 实现指定 GitHub 仓库资料同步，详见 [P4 交付](history/P4-FINAL.md)。WordPress 后续再考虑；Cordis 安装与扫描、游戏训练器不计入首版。首版模块只建设有限来源同步，不同时建设通用采集平台。

## 非功能验收

以下是待测目标而非已证明容量：功能矩阵至少三站；容量夹具计划包含 30 站、10 万资源、30 万发布记录，每条发布最多三种语言。基准环境建议 4 vCPU、8 GiB、SSD，实际资源分配写入报告。

P5 计划采用 20 并发浏览客户端，测量冷/热缓存下列表、搜索、详情、配置发布、登录与任务并行，记录延迟分位数、错误率、查询量和内存。延迟门槛在 P0/P1 基线后确定。该夹具不是硬性站点上限或无限扩展承诺。

版本号和短 TTL 管理普通配置；停站、下架和权限使用权威门控；首版默认不使用动态 HTML 的 CDN 全页缓存。细则见 [公共数据访问](DATA-ACCESS.md)。

业务导入导出采用版本化 JSON 与媒体清单，记录类型、站点、语言和稳定标识，不导出密码、会话或 OAuth 密钥。导入先 dry-run，检查版本、引用、重复项与站点映射，明确部分失败和重试结果。

业务导出不代替备份。提供数据库与媒体备份和隔离恢复步骤；备份记录应用版本及密钥引用需求，密钥通过独立受控方式保存。日备份为示例调度，RPO/RTO 依据部署选择和恢复演练报告，不承诺未测数字。

任务持有租约、幂等键和重试次数；进程中断后可在租约过期时重新领取，避免重复发布。批量跨站发布按站事务执行，逐站报告成功/失败。数据库迁移记录执行状态；事务迁移失败回滚，非事务步骤给出重试与恢复办法，不对已有库自动运行破坏性同步。

P0 在迁入前逐项核查来源修订、许可证、归属与素材来源；未解决项不进入可公开实现。最终许可证在批量迁入前确定，不拖到 P5。用户已授权选择性复用，具体来源疑问逐项处理，不重复请求笼统许可。
