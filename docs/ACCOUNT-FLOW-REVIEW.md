# 账号页面异步流程 Review

日期：2026-10-19。范围为账号页自动续接与手动操作的浏览器请求归属，没有修改服务端认证协议。

## 问题与修复

带签名参数的独立账号中心登录页会自动读取现有会话并请求 OAuth 续接。旧实现与手动登录并行：用户尝试登录另一账号且收到失败提示后，迟到的旧会话读取或续接结果仍可能跳转旧账号对应的目标；迟到的自动错误也会覆盖手动反馈。

现在同一页面一旦开始手动操作，自动流程不再发起后续续接，也不使用已发出自动请求的跳转或错误结果。手动操作失败后可以明确重试，自动流程不会恢复抢占。正常自动续接仍适用于没有手动操作的新页面，签名查询参数原样保留。

旧实现自动读取会话时未检查 HTTP 状态，将 503 的 JSON 错误对象视作真值并继续 POST。现在失败的会话响应不会触发续接。没有降低或替代服务端的签名、state、会话、账号空间和过期检查。

旧实现仅禁用按钮，重复的表单提交事件仍能发出多个认证请求。现在对手动操作设置进行中标记，同一请求结束前忽略重复事件，结束后解除标记并恢复按钮，允许用户重试。没有增加后端接口或改变认证限流。

浏览器丢弃迟到结果不会撤销已经发送的服务端请求，也不承诺作废已签发的授权码；安全校验继续由服务端负责。

## 验证设计

原四项新增控序回归在旧实现均失败，修复后通过，另补一个迟到自动错误分支：

- 阻塞旧会话读取，手动登录失败后释放旧会话；不再调用自动续接，不跳转旧账号目标。
- 阻塞已经发出的自动续接，在手动登录失败后分别释放成功/503响应；不跳转，也不覆盖手动错误。
- 会话读取返回503 JSON，不调用自动续接。
- 同一表单连续两次 requestSubmit，在途认证请求只有一次；失败完成后可以再次提交。

新增控序用例使用实际账号页面生成器和脚本，以及受控 API 响应。完整 P3 回归另验证真实 HTTPS、SMTP、共享账号、本地 OIDC 和现有会话恢复；不将浏览器夹具作为真实签名或外部平台联调证据。

另补原有提供方标签测试：内嵌 JSON 经 JSON.parse 后与原标签完全一致，且没有额外脚本标签。最初对配置转义的怀疑被该回归否定，原实现保持不变，没有宣称修复注入漏洞。
