## P8 覆盖

- 发布冻结：
  - 上传时写入 v1 历史版本，返回带版本号的地址；
  - 发布后只能访问已发布的版本，未发布版本和其他站点返回 404；
  - 旧地址 302 跳转到已发布版本，响应不缓存；
  - 替换图片后线上不变，重新发布后才切换到新版本，旧版本变为 404；
  - 迁移前的发布记录按 v1 处理。
- 服务端：
  - 替换：新版本同步写入 `media` 记录；容量只为新内容计算一次；文件数不变；超出配额返回 413；
  - 历史、恢复、按版本预览；
  - 删除版本：当前版本受保护，只删除没有其他版本共用的文件；
  - 权限与审计；
  - 上传去重只匹配各素材的当前版本；
  - 孤儿清理保留只被历史版本引用的文件；
  - 端到端：包括已下架的发布记录仍然阻止删除素材。
- 页面（浏览器测试）：
  - 批量上传 3 个文件，其中 1 个失败，另有 1 个在开始前被移除；
  - 遇到配额不足时停止剩余文件；
  - 替换、历史、恢复、删除版本；
  - 已发布版本的删除按钮被禁用，强制点击后服务端返回 409 并显示提示；
  - 只读用户看到错误提示，数据不变。

## 开发中修复的问题

- `Content.mediaUsage` 用 uuid 参数去比较文本字段，导致删除媒体返回 503。由服务端 agent 发现，已修复，P8 和 P2 都覆盖到了。
- 发布与删除版本之间的竞态：`material()` 读取当前版本时加 `FOR SHARE` 锁，让并发的替换必须等发布提交后才能进行，这样被冻结的版本在发布提交前不可能变成可删除的非当前版本。

## 未验证 / 保留

- 未运行 `pnpm test:docker`；Docker 测试使用媒体对象返回的 `url` 字段，该字段已改为带版本号的地址，预期仍然通过。
