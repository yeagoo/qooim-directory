# 内容编辑选择与异步结果 Review

日期：2026-10-18。范围为主档与站点发布记录编辑器中的异步读取、保存及刷新，不新增接口、数据库迁移或依赖。

## 复现和修复

未修复时，原17项内容回归通过；新增真实Chromium用例失败：选择A并请求新版差异，扣留响应后改选B，再释放A响应，当前资源仍为B，但candidate.slug实际被写成A。日志 `.local/content-selection-baseline.log`。这类问题发生在同一hash页面内，上一轮路由作用域不能替代编辑选择检查。

- 每个编辑器跟踪当前DOM节点及编辑代次。选中另一条、切换新建或手工编辑后，旧结果失效；页面被重新绘制后旧节点同样失效。
- 发布记录的差异、预览、可见性诊断共用“最新读取”序号；更晚发起的检查优先，后续写操作也使先前读取失效。差异只有在原编辑仍有效时才写入候选。选择或手工编辑会清空旧结果。
- 主档历史按原选择检查，切换新建会清空历史，不再给B展示迟到的A版本列表。
- 主档保存及发布记录的保存草稿、发布、下架在请求前捕获原编辑上下文和目标。服务端已提交的操作保留；用户改选或继续编辑后，迟到响应不重绘当前编辑器。刷新列表的查询完成时再次检查，失败时也不显示已经失效的刷新错误。保留原筛选和页码。

这里只防止异步结果覆盖新的编辑。没有自动合并本地后续输入与已提交版本：若同一条记录在保存期间又被编辑，保留文本不代表其版本基线已更新；继续保存仍须通过服务端版本检查，需重新载入并核对。切换选择不会撤销已经提交的事务；这与跨页面操作规则一致。分类及投稿审核的独立流程不属于本轮重构范围。

后续 [主档连续保存 Review](RESOURCE-SAVE-REVIEW.md) 已改善资源主档的本次确认版本接续；随后 [内容双版本接续 Review](CONTENT-SAVE-REVIEW.md) 也补齐了草稿、发布与下架的确认基线。上述限制保留为历史记录，当前行为以两份后续Review及操作协议为准。

后续分类/审核及多区域编辑保留的实现和验证见 [分类与审核 Review](CONTENT-MODERATION-REVIEW.md)。

## 验证

真实HTTP与Chromium覆盖：A差异迟到后选B、同条记录继续手工编辑、预览与诊断先后交错、旧诊断503提示、主档历史迟到与新建清空、内容草稿已经提交后切换并编辑B、主档已提交后切换并编辑B，以及刷新查询成功/失败时保留当前编辑。数据库直接核对原目标确实提交，不能把“迟到响应没有回写”误称为后端取消操作。

扩展首轮出现测试夹具版本错误：发布会消费草稿并递增版本，夹具把版本写死为1而被服务端冲突检查拒绝。已改用既有publications服务读取真实版本，没有放宽产品校验。修复后19项内容回归通过；追加刷新查询503后，用最终代码运行P1 15项、P2 19项、P4 17项共51项，全部正常退出0；发行回归10项同样通过。生产build及随后顺序执行的check均正常退出0，避免Next生成类型与类型检查竞争。

本轮只改既有后台JS和浏览器回归、文档，没有新增静态资产或部署变更；没有重复Docker整体验收、容量或P3认证联调，也没有把旧结果算作本轮通过。最终日志 `.local/content-selection-{tests,release,build,check,gate}.log`；源码候选 `.local/content-selection-review-20261018`。更新记录后重新生成归档并核对文件摘要；严格发行检查仍按四项许可缺口返回1。
