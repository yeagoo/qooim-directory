# 主档文件导入交互 Review

日期：2026-10-20。承接[资源保存确认](RESOURCE-SAVE-REVIEW.md)和[文件交换](CONTENT-EXCHANGE-REVIEW.md)，本轮处理主档文件导入的执行确认、列表恢复与未提交输入保护。

## 发现与修复

原先执行导入复用文件检查的 `submitFile`，返回结果依赖当前文件选择代次。写入已经成功但选择变化时，确认可能被当作旧读取丢弃；执行期间也未锁定文件和其他写入入口。现在写入结果归属于实际提交的文件，执行期间禁止换文件及重复导入，与主档保存和列表刷新互斥。检查导入仍允许选择新文件，旧检查结果继续按原文件代次忽略。

原先导入成功后整页调用 `renderResources`，清空主档表单及未提交备注；列表读取失败又会覆盖成功提示。现在立即显示导入确认及返回的结果版本，清除已提交文件，禁止旧文件直接再次执行；仅原位刷新当前列表和分页，不重绘编辑器。选择另一份文件后才开启下一次检查或执行。明确拒绝时保留文件和输入供显式重试；未知网络结果不会自动重发，也不能据客户端错误推断服务端未提交。

列表读取失败保留导入成功确认、结果和主档输入。旧列表编辑入口暂不可用，通过新增“刷新列表（保留编辑）”只读恢复，不再次执行导入。刷新期间仍可编辑主档输入；执行导入期间也保留主档输入能力，写入请求使用提交时的文件快照。

列表更新替换缓存记录，不修改编辑器原来审阅的版本。即使导入或另一操作者已经更新同一主档，本地未提交内容继续携带原 expectedVersion，服务端仍会按原规则拒绝冲突；只有明确选择列表里的新版，才载入新内容和版本。不将读取列表当作对本地编辑的自动合并或重新定基。

资源列表改用事件委托，使新增或刷新后的行仍能进入编辑。列表更新同步处理分页资格。局部按钮等待状态独立于普通内容页的监听器；迟到检查不能重新启用正在执行导入的控件。已有主档保存时继续输入、切换目标与确认版本更新的逻辑保留。资源导出的旧结果也受页面操作归属限制，不能在较新的写入后覆盖提示或触发旧下载；单纯键入不会改变这项操作归属。

## 验证设计

新增10项 Chromium 浏览器用例。最先8项在旧实现6项失败、2项通过，修复后全部通过；另补充手动刷新不采用外来版本，以及显式选择下一文件才允许新导入。

前8项覆盖执行期间重复事件/跨写入/文件选择保护、成功后保留输入与版本、读取失败后的只读恢复、明确拒绝后的显式重试、迟到检查、切换路由后的迟到确认、未提交新主档，以及保存期间拒绝并行导入。程序触发的重复事件用于验证处理函数自身也会拒绝等待中的操作。

使用真实后台页面与脚本、隔离数据库的后台会话，列表/写入结果由受控浏览器路由夹具提供；不把夹具当作真实资源持久化证明。现有完整 P1/P2 回归另覆盖真实保存、导入原子事务、冲突、跨站发布、审核和浏览器流程。显式 Promise 控制提交、检查与读取时机，验证请求数、请求版本、按钮、输入和列表，没有固定延迟猜测完成时机。
