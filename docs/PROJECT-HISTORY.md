# Qoo.IM Directory 项目历史总览

整理日期：2026-10-25。本文是一份总览，把项目的背景、各阶段、发版和协作规则集中在一处。细节以文中链接的原始记录为准。本文含内部路径和流程，属于本地交接文档，不能直接作为公开 README。

## 一、背景

- **起点**：原站群 `~/daohang/toolso-ai-open` 用一套 Next.js 应用承载十个品牌导航站。它按站点配置和页面分支演进，导致配置和站点范围耦合、页面逻辑重复、跨站内容和账号的边界不清。
- **决定**：
  - 重新开发、独立开源，项目放在 `~/daohang/qooim-daohang`。
  - 原站群保持原样：不迁移、不改生产、不删旧代码。toolso-ai-open 只读。
  - 已确认 toolso-ai-open 属于用户本人，借用它的代码时保留 Apache-2.0 归属头。
- **身份与发布信息**：
  - 品牌：Qoo.IM Directory；
  - 许可证：AGPL-3.0-only；
  - 仓库：`yeagoo/qooim-directory`；
  - 正式域名和公开仓库名待定。
- **产品形态**：
  - 面向个人和小团队，一个后台管理多个独立品牌的站点。
  - 资源主档和站点发布记录分开，资源要显式发布才会在站点上公开。
  - 新站点使用独立账号；共享账号中心冻结，只保留兼容（legacy）。
- **技术栈**：Next.js 16、TypeScript、PostgreSQL；用 Docker Compose 部署 Web、Worker、数据库和 Caddy 代理。

详见 [项目背景](PROJECT-BACKGROUND.md)、[开发方案](DEVELOPMENT-PLAN.md)、[交接总览](PROJECT-HANDOFF.md)。

## 四、协作与治理规则

- **授权**：用户已授权持续开发，开发、Codex 审查、修复、提交、合并、推送都不必逐次确认。以下事项仍须用户明确决定：
  - 公开发布和部署；
  - 打版本 tag；
  - 镜像证据签署。
- **镜像证据**：
  - 以下六个文件被固定校验：Dockerfile、.dockerignore、compose.yaml、compose.demo.yaml、pnpm-lock.yaml、package.json。它们或应用代码一变，证据就失效。
  - 失效后要按下面的流程重新采集，状态设为 pending，并写一份复核材料。
  - 只有 QooIM 本人明确确认后，才能填写 `complete` 和审核人字段；回复含糊的，先问清楚。
  - 文档会打进镜像，所以签署提交本身也会让镜像变化。惯例是签署提交之前构建的那个候选镜像。
- **刷新流程**：
  1. `docker build` 构建候选镜像；
  2. 把旧的 `app-inventory.json` 移开；
  3. 运行 `distribution.mjs inventory` 生成新清单；
  4. `git rm third-party/image-evidence/*.json` 删除旧证据；
  5. 运行 `image-license-evidence.mjs` 重新采集；
  6. 更新 `image-review.json`：写入新哈希，各范围设为 pending，旧审核保存为 `previousReview`；
  7. 写复核材料 `IMAGE-EVIDENCE-REVIEW-PACKET-*.md`。
- **秘密信息**：`.env` 和各种密钥都不提交；运营者密码不能输出。
- **toolso-ai-open**：只读，不修改、不迁移、不部署。以下素材不移植：头像、横幅等图片、network-logos、scraped 数据、品牌素材、simple-icons 品牌 logo。
- **开发流程**：
  - 每个里程碑开新分支；
  - 跑 check、build、P0–P17、`test:docker`。并行跑偶尔失败的用例要单独重跑确认；
  - Codex 只读审查，修正后再合并；
  - 写验收记录。
- **测试环境**：测试用隔离的 Postgres 容器（`scripts/test-p0.mjs`）。本地预览项目名为 `qooim-preview`，地址 `https://admin.localhost:8443/`。

## 五、当前状态与未完成事项（2026-10-25）

- **可用程度**：可以自托管试运行，是预发布版，还不是生产稳定版。
- **稳定版前必须完成的外部验收**：
  - 真实 GitHub 和 Google OAuth 登录；
  - 真实 AI 服务商；
  - 真实 RSS 和 npm 源；
  - Passkey 真机。
- **需要用户决定**：域名和公开仓库名，并在公开前做一次最终审查。
- **容量**：只做过共享主机上的短期基线（30 个站、10 万条主档）。如需生产容量结论，要先定目标，再用独占资源测试。
- **预览环境**：library 站点处于停用状态，是否重新启用待用户决定。
- **下一轮候选功能**（尚未承诺）：
  - 向量查重；
  - 按规则自动分发；
  - zh/en 以外的语言；
  - 链接失效时提醒下线、批量改分类；
  - 投稿一次投给多个站点；
  - 分发效果统计。
- **长期不做**：配置自动三方合并、跨域静默 SSO、计费、拖拽建站、服务端图片转码（避免再次引入 sharp/libvips）。
