# 个人投稿历史分页 Review

日期：2026-10-20。延续 [读者提交确认 Review](READER-COMMIT-REVIEW.md)，补齐个人投稿记录超过 100 条后的访问路径及稳定排序。沿用现有个人接口、身份隔离、每页 100 条及后台页码校验规则，不修改依赖、正式迁移或旧站。

## 问题与修复

旧个人查询固定返回最近 100 条，没有页码入口；更多历史只能保留在数据库，读者无法从个人页查看。查询只按 created_at 降序，相同时间的记录在截断边界没有固定顺序。

`GET /api/me/submissions` 现在支持可选 `page`，默认为 1，校验整数范围 1–100000。响应仍是原数组，每页最多 100 条，原调用方式不变。服务层同样校验页码，按 `created_at DESC,id` 排序后使用 LIMIT/OFFSET。查询仍只采用已验证会话的规范用户 UUID 和当前站点；请求参数不能改变用户或站点归属。

个人页增加独立的投稿页码及上一页/下一页按钮。翻投稿页保留收藏页码与未提交表单；语言选择只重置收藏页，投稿历史仍包含本站该用户的所有语言。成功投稿后历史回第一页，收藏页码及请求期间新增的表单编辑保留。原提交确认、读取代次和消息归属保护继续生效。

响应未新增总数或分页对象。满 100 条时提供下一页，末页恰好满页时可能进入空页；空页明确提示并保留上一页入口，不显示成“还没有投稿”。这是实时 OFFSET 分页，翻页期间新增记录可能移动边界，不承诺跨页数据库快照。相同数据集及相同时间的记录以 ID 稳定排序。

## 验证

新增 8 项回归：

- 数据库插入 103 条同时间历史，逐页验证顺序、完整性、无跨站或跨用户混入及越界空页。
- 真实注册登录后经 HTTPS 验证默认数组、第二页、非法页码 400、允许的最大页码空数组及跨站未登录 401；查询中的 user_id/site_id 无法改变范围。
- 浏览器验证收藏/投稿独立翻页、语言切换和输入保留，以及满页后的空页返回。
- 重复旧分页控件不跳页，迟到 200/503 历史响应不覆盖较新的读取。
- 投稿成功回第一页并保留收藏页和新编辑；第二页读取失败仅通过 GET 重试，保留页码及输入。

最初 4 个反例在旧实现全部失败，修复后通过；扩展后共 8 项通过。数据库历史通过测试 SQL 构造，不绕过或改变产品每小时 10 条限制；浏览器交错路径使用确定性接口响应，真实 HTTP 用例另行验证身份及参数边界。

生产构建完成后执行完整 P1/P2/P3/P4 回归 241 项，发行测试 69 项，共 310 项通过；类型与边界检查通过。文档保存后重建源码归档，并核对工作区、导出目录与归档逐文件摘要和公开本地链接。未重验 Docker 安装、容量或真实外部 OAuth。
