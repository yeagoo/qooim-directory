# 内容批量发布 Review

日期：2026-10-20。本轮把既有 `POST /admin/api/content/batch-publish` 接到后台内容页，不新增批次事务语义，也不改变单条发布协议。

## 交互

- 发布记录表对 `draft_version > 0` 的行显示勾选框；没有草稿的行不可选。
- “选择有草稿”只勾选当前页可发布行；“批量发布选中”按选中行构造最多 20 项。
- 每项携带自己的 `{siteId, resourceId, locale, expected: {published, draft}, operationId}`，逐项独立事务。
- 返回结果按项显示成功/失败；失败项保留原草稿。完成后刷新当前分页列表，保留其他编辑区域。
- 批量按钮只对站群管理员显示；站点编辑仍按单条发布。服务端仍以全局管理员权限校验，隐藏按钮不代替权限。

## 边界

- **不是整批原子发布**：一项失败不会回滚其他成功项。需要整批一致时应拆成独立操作或另行设计。
- **没有逐项重试按钮**：失败后保留草稿，解决冲突后可再次批量提交；每次提交生成新的 operation UUID。
- **不跨站点批量**：入口在单站内容页，`siteId` 固定为当前站点；跨站批量需要另行设计权限和部分失败呈现。
- **不改变版本协议**：仍检查当前发布版本与草稿版本；外部修改导致 409 时，列表刷新后重新选择。
- **不调度**：批量发布立即执行，不进入后台任务队列；大数量或定时发布不在本轮范围。

## 验证

- `tests/p2/content.test.ts` 新增浏览器用例：在 `#content/notes` 勾选两条草稿、点击批量发布、等待“2 成功，0 失败”。
- 既有的 batch-publish API 测试继续覆盖“一项成功、一项冲突时各自独立事务”。
- 使用隔离 PostgreSQL 与 HTTP + Playwright 实跑通过：两条草稿批量发布返回“批量发布完成：2 成功，0 失败。”
- `pnpm check`、`pnpm build` 通过。
- 完整 P2 套件需要免密 sudo 起 Docker 和改 hosts；当前沙箱未跑全量，新增浏览器用例与本次 HTTP 实跑覆盖了主要交互。

- 没有加入“全选跨页”或导出批量结果；当前只选择当前页。
