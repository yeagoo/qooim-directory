# 目录收藏与共享提示 Review

日期：2026-10-20。延续 [读者退出交互 Review](READER-SIGNOUT-REVIEW.md)，修复目录收藏重复事件及收藏、退出、个人写入交错时的提示归属。复用现有接口与个人页动作代次，不修改站点、账号、收藏或投稿的业务协议。

## 问题与修复

目录收藏原本只禁用被点按钮，没有事件处理守卫。原生点击受限，但程序派发的重复事件仍可并行写入。现在页面按 resource_id 维护等待集合，先检查等待状态及节点仍在页面，再发送 POST；当前页面初始化时取得的同资源收藏按钮同步禁用与恢复，不同资源可独立操作。完成或失败仅解除对应资源状态，失败后可以明确重试。这是页面内保护，不是跨标签页或服务端互斥，也不新增动态模板挂载协议。

目录原本由每个异步结果直接写入同一个提示区；个人页有自己的动作代次，退出又不参与。先收藏资源 A，再收藏 B，A 的迟到成功或失败可能覆盖 B 的结果；收藏与退出、个人写入与退出也会互相覆盖。

现在将原个人页的 actionVersion、confirmation、beginAction 提升为页面共享状态。收藏、投稿、取消收藏和退出均在开始时取得提示归属，并清除上次确认；只有仍持有归属的结果可更新提示。等待状态始终按各操作分别解除，不因消息过期锁死按钮。成功退出仍返回本站首页，不因另一动作取得提示归属而取消已确认的退出。

投稿和取消收藏完成后的列表读取显式传递写入开始时的 messageVersion；自动纠正页码继续传原值。否则旧 POST 返回后调用 load() 会重新捕获新动作代次，虽不再展示旧确认，仍能用旧刷新清除新退出错误。读取仍可更新列表，只在版本匹配时更新提示。列表读取代次、独立翻页、表单编辑保护沿用原规则。

## 验证

新增 8 项浏览器回归：重复收藏事件拦截与失败重试；旧收藏成功/失败不覆盖较新资源结果；旧收藏成功/失败不覆盖退出错误；旧退出失败不覆盖新收藏确认；旧投稿、旧取消收藏提交后的刷新分别保留新退出错误。也检查不同资源按钮独立恢复及请求体保持原协议。

8 项在旧实现全部失败，修复后全部通过。使用实际目录/个人页 HTML 与浏览器脚本，控制 API 响应顺序；会话及写入采用受控响应，不宣称这些用例证明真实登录、数据库提交或跨标签页行为。服务端隔离、授权、真实收藏与退出由已有回归另行验证。

生产构建完成后执行完整 P1/P2/P3/P4 回归 259 项，发行测试 69 项，共 328 项通过；类型与边界检查通过。源码工作区、导出目录和归档逐文件摘要及公开本地链接另行核对。不重验 Docker 安装、容量或真实外部 OAuth。

品牌、真实 OAuth 联调、4 项依赖许可证材料及 7 项镜像核查仍为发行前置项，原有门禁保持阻断；旧站未修改。
