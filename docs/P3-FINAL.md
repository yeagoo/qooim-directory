## Review 修复

- 按 OIDC 规范保留 issuer 原值，只在发现 URL 构造时去除末尾斜线；提供 basic/post 客户端认证配置。
- 核对安装源码后统一使用 `/sign-in/social`；不沿用其他版本 genericOAuth 的旧路由。
- 绝对期限不仅控制业务权限，认证协议入口也清理无效残留库会话，防止刷新或再次授权续活；共享站检查中心绝对期限。
- 密码重置撤销同空间该用户的所有规范会话；同邮箱外部身份不能静默绑定既有密码账号。
- 邮箱验证保留中心签名授权查询，验证后可继续返回原共享站；未配置邮件的找回页面回到登录页。
- 所有认证 POST 请求都有 16 KiB 正文限制，超限取消流；邮箱操作另有持久限额。
- 私有代理头先校验再移除；普通转发头不能选择 origin 或限流 IP；生产验证开关拼写错误和不完整 SMTP 凭据拒绝启动。
- 邮件租约有 fencing token、最多 5 次投递；最终失败清除敏感正文，不提供无法恢复正文的重试入口。每轮只处理一封，限制 SMTP 故障对其他任务的阻塞。
- 模板和 SDK 都经过依赖门禁，公开内容仍先经过统一数据层；冻结 DTO 不等于沙箱。
- 提供方标签在 HTML 与嵌入 JSON 中分别转义；手机布局测试检查横向溢出。

Review 是实现者审查与回归测试，不是第三方安全审计。AI 示例尚不代表已获部署者人工批准上线。

## 保留边界

- 真实 GitHub/Google 联调待部署者提供应用配置和可用回调域名；出现平台差异后继续修复，不能由本地协议通过推断平台验收通过。
- SMTP 至少一次投递，崩溃窗口可能重复；不承诺外部邮箱送达或进入收件箱。
- 无任意模板上传执行、认证账号自动合并/绑定界面、已有账号空间迁移工具。
- 未据三站功能测试宣称 30 站容量；P4 首个垂直模块仍需选定，P5 负责容量、完整备份恢复及发行检查。
