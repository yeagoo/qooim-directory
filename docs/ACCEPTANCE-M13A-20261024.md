## Codex 审查

用 Codex CLI（只读模式）审查了本分支相对 `main` 的改动，共 7 条，逐条核实后都属实，已修复：

1. **删除媒体有竞态（高）**：引用检查在删除事务之外。如果检查后有发布并发提交了对这张图的引用，已发布的页面会永久 404。这个问题在 M8 的封面图上就存在，logo 沿用了同一个检查。现在删除和删除旧版本时，都先锁住媒体记录，在同一事务里重新检查引用。新增的并发测试在去掉这次修复后会失败。
2. **目录查询性能（高）**：分类名、标签名的聚合和日期格式化，原来会对每条匹配结果都算一遍，然后才分页。现在只对当前页的条目计算。
3. **迁移补时间（中）**：曾经发布、后来下架的条目没有补上时间，重新发布时会把首次发布时间覆盖成新日期。现在凡是有发布记录的条目都会补。迁移 015 还没在任何正式数据库上执行过，所以直接修改了它。
4. **basic、editorial 模板丢标签筛选（中）**：分页链接和搜索表单会丢掉标签条件。现在分类页、标签页的分页走各自的地址，搜索表单保留标签。
5. **Markdown 外链判断可被绕过（中）**：`//host` 和 `/\host` 这两种写法没有被当作外链。现在先把反斜杠归一化再判断，链接本身不改写。
6. **toolso 侧栏数量不对（低）**：用 `?tag=` 筛选时，侧栏“全部”显示的是筛选后的数量。
7. **后台清空语言报错（低）**：清空一种语言的名称和说明时，如果这种语言还有富字段，保存会报错。现在整种语言一起删除，和以前的行为一致。

修复后重新跑了上面的全量回归。

## 已知限制与后续

- **富字段只能在 JSON 里编辑**：tagline、功能、FAQ、长文等字段，后台只能在完整 JSON 中编辑，没有专门的表单。M13b 的 AI 补全会生成这些字段的候选。
- **react-markdown 依赖 Next 打包**：react-markdown 的模块会导入 React hooks。在 Next 构建中它被打包进路由，同步的 `Markdown` 组件不会调用 hooks，所以能正常工作。如果以后把它配置成 Next 的外部包，渲染会失败。
- **basic 和 editorial 模板还不显示新字段**。
- **sitemap 还没有收录标签页**，和首页、分类页一起放到 M14。
- **镜像 evidence 仍需重新采集**：`package.json` 和 `pnpm-lock.yaml` 又有变化。按原计划，在 M13–M15 完成、代码冻结后统一重新采集，再交 QooIM 签名。
- **M13b**：榜单（热门、编辑精选）和 AI 补全富字段。
