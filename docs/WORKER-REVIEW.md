# 后台任务失败隔离 Review

日期：2026-10-19。范围是当前独立系统的安装验收与后台任务异常处理，没有修改旧站或生产部署。

## 问题与修复

原先 `runJobs` 中任一配置投递异常都会直接退出循环，GitHub 同步、邮件和会话维护均跳过；邮件队列基础设施异常也会跳过会话维护。发布事件虽已持久化退避重试，其他任务仍会受到这一轮异常影响。

现在按现有任务类别顺序执行并收集异常；认证准备中的单实例异常也不阻止尝试其他候选实例。配置投递异常仍结束本轮配置消费，保留原租约、回滚、次数上限和退避，不在同一轮反复重试故障队列；后续独立类别继续执行。全部类别尝试完后统一抛出 AggregateError，worker 入口沿用通用日志和下一轮重试，不输出原始异常中的敏感信息。成功投递计数只计入已完成事件，不把租约丢失计为完成。

有异常的循环不写成功心跳。既有两分钟健康窗口保留：偶发异常不会立即使健康状态失败，持续异常才会使成功心跳过期。队列正常记录的单项失败仍由原任务状态诊断，不能仅凭 worker 健康推断所有业务任务成功。

## 故障验证

新增两项 P1 回归，修复前均失败，原有 15 项通过；修复后 P1 17/17 通过。

- 配置投递注入异常，验证邮件与会话维护仍执行、失败事件保留 pending/attempts/last_error、成功心跳不变；解除故障后同一事件和后续事件完成，不生成替代事件。
- 邮件与会话维护同时异常，验证会话维护仍被尝试，两个原始错误均保留在聚合异常中。

测试采用隔离 PostgreSQL，使用测试上下文恢复的故障注入；没有改变生产配置、数据库迁移或依赖版本。
