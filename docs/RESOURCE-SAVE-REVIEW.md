# 资源连续保存版本 Review

日期：2026-10-18。本轮改善资源主档在保存期间继续输入的版本接续，沿用现有乐观锁和 `{version}` 成功响应。

## 问题与处理

此前编辑保护会保留保存期间的新输入，同时丢弃本次成功响应的版本。已存在主档从版本1保存为2后，界面第二次仍按版本1提交，遭遇自己造成的冲突。新增真实HTTPS浏览器测试在原代码上26项通过、1项失败，直接捕获第二次提交的expectedVersion为1。

资源保存现在分别处理写入确认与编辑器回填。成功响应先按原目标更新当前列表缓存与显示版本；当前选择代次、标识和DOM仍一致时，编辑器基线接续本次确认版本，继续保留后来输入的内容。新建主档也会锁定已创建的标识，避免下一次仍按新建提交。切换到其他主档不会重绘编辑器、覆盖输入或提示；重新选择原主档时使用本次已确认缓存。

当前目标保存失败时，后续输入仍保留，并显示失败原因，不虚构版本递增。写入成功但后续列表刷新失败会明确提示“已保存”，当前编辑器仍采用本次确认基线。网络中断导致提交结果不明时应重新查找核对，不能把缺少成功响应理解成事务未提交。

没有从任意列表查询结果自动接受外部版本，没有合并外部内容；其他操作员在此后提交新版本，下一次本地保存仍按自己的已知版本接受服务端冲突检查。内容发布记录的双版本协议不在本文轮次范围内，后续实现及验证见 [内容双版本接续 Review](CONTENT-SAVE-REVIEW.md)。
