# P0 第四轮：会话对账与恢复边界

历史记录：当前 P0 状态以 [最终验收](P0-FINAL.md) 为准，以下保留当轮发现与限制。

日期：2026-10-18。会话对账已接入隔离认证原型；尚未交付正式共享表认证服务。

## 范围纠正

[账号设计](IDENTITY.md) 与 [P0 验证计划](P0-VALIDATION.md) 一直规定：首版不提供已有用户自动迁移工具，A12 只验证迁移模型。第二、三轮进度把完整账号迁移执行与中断恢复列为 P0 阻塞，扩大了原定范围。本轮恢复原约束，没有删除失败场景或将未通过测试改名为完成。

A12 仍需补充重复收藏及权限冲突的模型演练；当前只有邮箱冲突报告。完整迁移工具、双方账号控制权确认、冻结写入、批次执行及检查点恢复属于后续功能，未实现且不纳入首版承诺。

## 实现与 Review

新增 `p0/internal/session-lifecycle.ts`：

- `auth_session_inventory` 汇总固定四个测试角色的认证库会话。表名来自代码中的固定列表，不由 Host 或请求指定。
- `auth_valid_session` 同时验证本地认证库会话、规范会话、用户、站点成员、站点状态，以及共享站的中心认证库和规范会话。请求鉴权和对账复用这一入口。
- `SessionLifecycle.reconcile` 分批撤销无效规范会话，再清理超过五分钟宽限期的无效认证库会话。规范身份、桥接和会话记录保留，不按邮箱重新关联，不延长有效期，不复活已撤销会话。
- 清理与统计记录在同一事务提交，失败整体回滚，可重新执行。并发任务通过行锁和 `SKIP LOCKED` 分配候选；每次最多撤销 limit 条，四个角色各最多删除 limit 条，limit 限制为 1–1000。
- 成功运行记录只保存完成时间、撤销数和删除数，不保存 token、邮箱或 Cookie。桥接对规范会话增加唯一约束。

| Review 发现 | 修复 | 验证 |
| --- | --- | --- |
| 只检查中心认证库会话，未检查中心规范撤销 | 有效性查询增加中心规范会话、用户和空间一致性检查 | 中心规范撤销后 A/C 请求即时拒绝 |
| 删除钩子或桥接失败后可能残留状态 | 对账撤销无效规范会话并清理失效认证库记录 | 并发对账、再次执行、保持有效独立站会话 |
| 新登录的 after-hook 尚未结束可能被误清理 | 认证库记录保留五分钟宽限期 | 新孤立会话保留，超过宽限期清理 |
| 清理后统计写入失败可能留下半批结果 | 清理和成功统计共用事务 | 注入统计约束失败，确认清理回滚，再执行成功 |
| 表改名不再能注入视图依赖故障 | 改为暂时移走授权视图本身 | 数据库授权入口不可用时返回 503 |

数据库视图按对象标识维护依赖；因此原先“改名成员表使授权查询失败”的测试在引入视图后失效。修正了故障注入方法，没有降低预期错误状态。

## 行为限制

- 对账不代替实时鉴权。中心规范撤销在下一请求就生效，不等待任务执行。
- 封禁、停站等导致会话失效后，对账可能永久撤销这些会话；恢复账号或站点后需重新登录。
- 五分钟是测试原型的维护参数。超长登录流程即使跨过宽限期也必须失败关闭；正式服务应规定登录超时并配合任务调度。
- 当前提供可调用的批处理入口，未部署定时任务、运维页面、告警或历史保留策略。失败通过异常反馈给调用者，失败尝试未单独持久化。
- 认证库会话自动续期不会自动延长规范会话，按较短有效期重新登录。正式共享表适配器、生命周期策略与动态站点仍待完成。
- 本轮测试通过事务故障注入证明批次回滚及重试，未声称认证服务崩溃、数据库断电和完整生产灾备通过。
