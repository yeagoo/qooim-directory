## 内容

- **后台页面按角色显示操作**：`/admin/api/sites` 返回当前操作者在每个站点的角色（`admin`、`editor`、`viewer`），媒体、采集、AI、对账四个页面据此隐藏或禁用无权执行的操作，并显示一行说明（`#access-note`）。权限仍以服务端校验为准：调用页面时如果没有传入角色信息，页面照旧显示全部操作。
  - 采集页：管理来源、立即同步、重试任务、查看候选历史只对站群管理员显示（与服务端一致）；站点编辑者可以审核候选；只读用户只能查看。
  - AI 页：只读用户不能保存配置和版本选择，也不能取消或重试任务；新建提示词版本只对站群管理员显示。
  - 媒体页、对账页：只读用户看不到所有写操作。
- **媒体文件在提交后删除**：事务内只记录哪些文件已不再被引用，提交后在站点锁内再次确认，然后删除。提交失败时，记录和文件都保留。上传或替换失败时，刚写入的文件按同样规则处理。删除文件出错时只记日志，留下的孤儿文件由孤儿清理处理。
- **媒体审计**：新增 `media.upload`（只在新建素材时写入，重复上传同一张图片不写）和 `media.delete`，与数据改动在同一个事务里。
- **保留期边界**：已结束但没有写入 `completed_at` 的采集任务，按 `created_at` 判断是否清理。

## 开发中发现并修复的问题

- **单条候选审核接口从 M5 起一直不可用**：`POST /admin/api/collector-candidates/<id>/review` 把带有 `site` 的整个请求体传给 `Collectors.review`，而后者用严格 schema 校验，导致每次请求都返回 400。采集页的“接受为草稿”“拒绝”按钮因此一直无法使用。这个问题在 `v0.2.0-rc.1` 中就已存在；批量审核不受影响。原有测试都是直接调用服务方法，所以没有发现。现已修复，并新增 HTTP 级别的回归测试：接受后生成草稿、拒绝生效、版本过期返回 409、候选不存在返回 404。这个问题由角色 UI agent 在测试中发现。
