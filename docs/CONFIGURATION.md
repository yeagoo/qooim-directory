# 站点配置协议

状态：配置核心协议已由 P0 验证，P1 接入后台、CLI、审计和任务。P3 已加入模板选择与严格参数 Schema，详见 [模板开发](TEMPLATE-DEVELOPMENT.md)；垂直模块扩展属于后续阶段。范围见 [开发方案](DEVELOPMENT-PLAN.md)。

## 模型和交换格式

每站一份完整配置快照，每站一份共享草稿。数据库已发布修订是运行时真相源；后台与 CLI 使用同一 Schema 和写入服务。

首版采用 JSON，包含 Schema 版本、导出类型、站点标识、基础已发布修订和完整配置；草稿导出另带来源草稿版本。字段与 CLI 示例见 [P1 操作](P1-OPERATIONS.md)。未知字段、错误站点、未知 Schema 版本报错，不静默丢弃。

普通配置包括品牌、启用语言、导航、模块开关和模板参数。账号空间绑定、域名迁移与业务数据独立管理，不通过普通快照重建。密钥只允许引用；新模板代码仍需构建部署。

## 完整快照语义

- 必填字段缺失报错；可选字段缺失重置为 Schema 默认值或明确未配置状态，每字段写明规则。
- null 仅对可空字段合法，不默认代表删除。
- 导航与区块是有序列表，元素有稳定 ID；首版整列表比较替换，不逐索引合并。
- 数组缺项表示候选配置移除，差异页面显示删除；不删除其引用的业务记录。
- 重复 ID、非法父子关系、不支持语言和缺失引用在发布前拒绝。
- 停用模块保留数据；删除资源、用户或分类实体不是快照缺项的副作用。

## 静态页面

配置可选增加 `pages` 对象，未提供时规范化为 `{}`，旧配置不需要迁移。支持的 key 固定为 `about`、`privacy`、`terms`、`contact`；每个 key 可分别提供 `zh` 和 `en`：

```json
{
  "pages": {
    "about": {
      "zh": {"title": "关于本站", "content": "## 我们是谁\n\n这是一段 Markdown。"},
      "en": {"title": "About", "content": "## Who we are\n\nThis is Markdown."}
    },
    "privacy": {
      "zh": {"title": "隐私政策", "content": "我们只收集运行服务所需的信息。"}
    }
  }
}
```

- `title` 去除首尾空白后必须为 1–100 字；`content` 是最多 20,000 字的不可信 Markdown，可按空行分段，模板不得把其中的 HTML 直接插入页面。
- 只有配置了某语言版本，`/<locale>/<key>` 才存在；其他语言和未配置的 key 返回 404。canonical 指向自身，hreflang 和 sitemap 只列实际存在的语言版本。
- 若 `catalogPath` 与页面 key 相同，目录路由优先；该 key 不再作为静态页面、sitemap 页面或 toolso 页脚链接出现。
- 模板实现可选 `renderPage` 时使用模板外壳；未实现时由服务器输出转义后的段落兜底。字段定义和徽章路由见 [模板开发](TEMPLATE-DEVELOPMENT.md#m15静态页面与收录徽章)。

## 草稿与并发

导入生成候选变更，先比较和校验，保存时检查读取的已发布修订及共享草稿版本。后台执行同样检查。

已有共享草稿时，导入必须展示与草稿差异，显式决定替换，并校验当前草稿版本。版本变化则拒绝保存，保留候选输入供比较。首版不自动合并不同字段，也不提供默认强制覆盖。

页面只读刷新可保留未提交内容并读取新版本，但不能沿用旧版本的替换授权：若 revision 或 draftVersion 变化，清除旧替换勾选并提示重新比较确认。导入文件的原始基础版本不随页面刷新改写。交互与失败恢复证据见[配置编辑 Review](history/CONFIG-EDITOR-REVIEW.md)。

重复保存相同规范化内容可作为无变更返回，但仍先验证版本，不能让幂等优化绕过冲突检查。

## 发布与回滚

发布同时比较线上修订和草稿版本，重验引用、权限、模块及模板兼容性。单个事务写不可变修订、更新当前指针，并记录审计和待处理刷新事件。

提交前失败，线上指针不变；提交后刷新失败，状态为已发布且刷新待重试，不报告未保存。响应丢失后按操作标识查询，重试不重复发布。

回滚将历史快照作为新草稿，按当前代码和 Schema 重验后发布更高修订；不能降低版本号。模板不存在或旧 Schema 无法转换时阻止发布，提示修复。

跨站批量操作逐站报告结果，不承诺全批原子发布。传播机制见 [公共数据访问](DATA-ACCESS.md)。

## 延后能力与验收

自动三方合并、数组智能合并、每用户独立分支草稿、后台自动提交 Git 延后。后台和文件编辑、冲突、预览发布、导入导出和回滚保留。

验收覆盖并发编辑、删除重排、重复导入、跨站误导入、旧版本、发布中断及回滚依赖失效，清单见 [P0 验证计划](history/P0-VALIDATION.md)。失败必须证明线上快照完整且未被部分覆盖。
