# 成员与权限页面 Review

日期：2026-10-19。承接[账号与任务控制](ACCOUNT-CONTROL-REVIEW.md)的事务权限审查，继续检查后台成员页面的提交和读取失败路径。

## 发现与修复

原实现只在通用按钮监听器中禁用当前按钮，添加、授权、撤销和停用可同时执行；处理函数也没有等待判断。现在四种操作与手动刷新共享等待状态，并在处理函数检查状态。等待期间冻结相关输入与按钮，避免改选成员、站点或角色后误解请求目标。恢复成功前不接受第二次写入，后台导航仍可切换。

四种操作原先在 POST 成功后读取列表，GET 失败的错误会覆盖成功提示，并重新启用旧按钮。现在保留具体成功确认，单独说明列表刷新失败；旧表单和操作按钮保持禁用，提供“刷新列表”只读恢复。手动刷新不重新提交操作，失败可再读，成功后按新列表重新绘制。

添加成员收到明确成功响应后，立即清除本次邮箱和初始密码，再读取列表；即使列表读取失败，已提交密码也不会继续留在表单。提交被明确拒绝时保留输入，方便修正后再操作。网络或响应错误不会自动重发，不承诺服务端未提交。

权限操作原先重绘整个页面，会清空尚未提交的添加成员表单与权限选择。现在授权、撤销、停用及手动刷新保留本视图内的未提交邮箱、密码、成员、站点和角色选择。只有明确添加成功才清除对应添加输入。输入保留仅在当前视图内，不写 localStorage、sessionStorage、URL 或日志；切换页面和刷新浏览器没有新增草稿持久化。

沿用既有作用域校验，旧请求的迟到结果不覆盖新页面。服务端接口、事务权限与审计仍按原有规则处理，没有修改角色模型或承诺不同浏览器标签页之间互斥。

## 验证设计

新增12项 Chromium 浏览器回归：四种操作分别验证等待互斥和提交成功后读取失败恢复，共8项；另验证正常权限保存后保留未提交表单、创建被拒绝后输入和操作恢复、迟到停用响应不覆盖任务页，以及手动刷新互斥/读取失败/输入恢复。

最先11项在旧实现9项失败、2项通过，修复后11项全部通过；随后补充手动刷新恢复用例。使用真实后台页面和脚本及隔离数据库的后台会话，列表/写入由受控路由夹具响应。夹具验证页面行为，不代表重新执行真实成员变更；服务端行为由既有 P1 HTTP/数据库回归覆盖。

显式 Promise 控制等待时机，核对请求次数、按钮/输入状态、密码清理、提示、选择和导航归属。重复触发包含绕过原生 disabled 的 DOM 事件，确认处理函数自身也拒绝等待中的操作。没有用固定延迟猜测操作是否完成。
