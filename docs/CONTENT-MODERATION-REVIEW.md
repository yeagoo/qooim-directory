# 分类与投稿审核的编辑保留 Review

日期：2026-10-18。延续 [内容编辑 Review](CONTENT-EDITOR-REVIEW.md)，处理该轮保留的分类和审核独立流程。复用现有API、权限、版本和事务，没有修改数据库迁移、依赖或旧站。

## 复现及修复

原19项内容回归通过，新增分类保存用例在旧代码下失败：发布候选中已输入的description因分类保存后的整页刷新消失。日志 `.local/moderation-baseline.log`。这不是用户在保存中继续编辑才出现的问题，保存前已有的其他区域输入也会丢失。

- 分类保存只回填分类列表和服务端确认的版本，不重置发布候选或审核说明。响应到达时若已切换分类，不改写新选择；仍在同一分类继续输入时，文本保留，版本基线仅前进到本次实际确认的版本。外部并发更新仍触发409，保留本地输入，不自动替换为外部版本。
- 审核逐篇回填状态，成功后移除该篇终态操作控件。提交期间只锁当前投稿的两个决策按钮和说明输入，其他投稿可以继续编辑；失败则恢复控件。接受继续只生成资源主档和本站草稿，不自动发布。
- 发布记录改为独立局部刷新；发布记录自己的保存、发布和下架也不再整页重建，从而保留反向的分类输入和其他投稿备注。新审核草稿进入当前页发布列表后可以直接选择；排序使记录落在其他页时，须翻页或按返回资源标识处理，不能把分页列表当成完整全库。
- 列表刷新只接受当前视图中最新一轮结果。发布操作待确认的选中版本会被后续有效刷新接续，避免旧响应回退版本，或新刷新遗漏已经提交的草稿基线。
- 已提交审核与列表刷新失败分开处理：审核状态仍为accepted，终态按钮不恢复，提示通过“刷新发布记录”单独重试。网络故障导致提交结果不明时，仍应重新载入核对服务端状态；没有宣称为审核增加幂等接口。原先的pending/version事务检查继续防止重复生成资源。

## 验证范围

真实Chromium和HTTP覆盖分类切换、提交期间继续输入、连续保存采用已确认版本、外部冲突、各区域互相保留输入；同篇双决策只发送一次、其他篇说明保留、接受/拒绝、审核失败恢复、接受后仍不可公开、已提交后列表503以及单独重试不重复生成资源。

还人为扣留保存后的旧列表，再发起新的列表刷新，释放旧响应后继续发布，验证已提交草稿版本能被新刷新接续。分类和审核的局部DOM回填始终使用转义或textContent。

局部刷新后同步分页按钮；验证接受草稿使记录总数从99增长到100、101时仍能进入第二页，并返回第一页。已接受投稿即时及重新载入后均展示生成资源标识，用于定位其他页中的草稿；长标识复用已有可换行样式并检查390px布局。

首轮修复后内容20项通过，扩展22项通过。最终版本P1 15项、P2 23项、P4 17项共55项回归，以及发行10项回归全部正常退出0，共65项不同回归，不累计中间重跑项。生产build及随后顺序执行的check均正常退出0，避免Next生成类型竞争。

本轮没有新增路由、静态资产、依赖或数据库迁移。没有重复Docker整体验收、容量或真实OAuth联调，不将旧日志记为本轮通过。日志 `.local/moderation-{baseline,tests,release,build,check,gate}.log`；最终源码候选 `.local/moderation-review-20261018`。更新记录后重建归档并核对文件摘要，严格gate按四项许可缺口退出1。
