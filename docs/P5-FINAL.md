# P5 运行与发行准备验收

本轮交付加密数据库备份、隔离新库恢复、源码归档/获取入口、依赖通知清单、公开候选扫描和容量工具，并完成 Review 修复。用户已选择 AGPL-3.0，项目声明为 `AGPL-3.0-only`。本轮技术准备已交付；品牌、外部账号联调和分发许可核查尚未全部完成，不能据此宣称公开发行已就绪。

操作命令见 [P5 运维](P5-OPERATIONS.md)，完整许可证见 [LICENSE](../LICENSE)。旧站和生产环境未改动；没有创建或推送公开仓库。

## 实现和 Review

- `scripts/backup.mjs`：数据库自定义归档流式 AES-256-GCM 加密，认证密钥与备份密钥分离；先验证认证实例密文能被传入密钥解开。清单包含源码摘要、版本、迁移、备份时间、PostgreSQL 版本和密钥指纹。
- 恢复先完整验证密文，再创建不存在的新库；错误密钥、损坏归档、篡改清单、源码/迁移不匹配、已有库、保护库名均拒绝。事务恢复失败会回滚，保留本次新建空库，不删除原库。
- `scripts/release.mjs`：按明确目录/文件清单导出完整构建与测试源码，拒绝符号链接及嵌套凭据路径，扫描内部绝对路径、私钥、Token 和字面密钥；规划日志和内部背景排除。
- 构建生成本部署源码归档，在有效站点/后台 `/source.tar.gz` 提供；模板服务端出口与普通页面均添加获取链接，未知 Host 保持 404。早期测试发现模板不走通用 document，已在模板出口修正遗漏。
- 安装树依赖通知从实际包内 LICENSE/NOTICE 或含完整许可文本的 README 提取；缺失项单独列出，严格发行检查会失败，不能静默视为全部许可核查通过。
- 完整回归暴露 P4 浏览器测试操作 inert 旧 DOM 的就绪竞态。修正为等待排队提示及刷新结束，并人为延迟详情响应 150ms，保留严格交互断言；未增加超时或自动重试掩盖失败。真实页面已有 inert 加载防护。
- Compose 增加 `APP_DATABASE`，供恢复验证后选择新库，默认仍为 network；不改变初始数据库，不自动切换任何部署。

已应用的 001–005 SQL 均未改写，没有新增依赖或迁移；没有复制旧平台源码。

## 运维验证

6 项自动化覆盖备份/恢复端到端、密钥/完整性/版本失败路径、参数与路径保护、源码导出、源码获取 Host 边界，以及真实 PostgreSQL 权限故障触发的事务恢复回滚。

小型恢复夹具验证了：原公众会话继续可用、新公众登录、后台登录、收藏、主档私有字段、公开目录、配置修订、加密认证秘密和待消费发布事件。全量容量夹具恢复后再次核对 30 站 / 10 万主档 / 30 万发布及迁移；不把小夹具耗时用于容量恢复估算。

导出源码在独立目录执行 `pnpm install --frozen-lockfile --offline`、`pnpm check`、`pnpm build` 成功。源码包路径/内部材料排除与 Markdown 相对链接检查通过。源码归档不会带出根项目的 node_modules 或 `.local`。

## 容量短基线

实际环境：Node 24.18.0，Linux ARM64，共享宿主机可用 15 逻辑 CPU、约 23.5 GiB 内存。PostgreSQL 单独限制 4 CPU / 6 GiB；Next/Worker 堆上限分别 2048/1024 MiB，应用和浏览器没有整机 CPU/内存配额，磁盘 SSD 等级未核实。

夹具：30 独立账号站点、100,000 主档及版本、300,000 发布及历史、中英两种语言。真实 Next 生产构建、独立 Worker 与 20 个 Chromium 上下文并行；80 次页面导航、20 次密码登录与会话检查，521 个 HTTP 响应零错误。后台共用配置服务同步发布 3 次，另一个进程成功消费到第 3 修订，跨进程配置读取通过。

| 场景 | 样本数 | p50 | p95 | p99 |
| --- | ---: | ---: | ---: | ---: |
| 应用首次列表 | 20 | 960ms | 965ms | 966ms |
| 热列表 | 20 | 925ms | 927ms | 928ms |
| 搜索 | 20 | 427ms | 432ms | 433ms |
| 详情 | 20 | 183ms | 185ms | 185ms |
| 本地密码登录/会话确认 | 20 | 357ms | 369ms | 371ms |
| 配置服务发布 | 3 | 43ms | 84ms | 84ms |

测量窗口约 8.4 秒（含配置传播等待），整项测试含装载/恢复约 44 秒。SQL 调用 3272 次，含 Worker 和配置调用；累计执行约 18.7 秒可因并行大于测量窗口。Next 采样 RSS 峰值约 321 MiB；PG cgroup 峰值约 1533 MiB，包含夹具装载阶段。数据库大小约 625 MiB。

预先设置的开发基线门槛为读 p95 ≤ 3000ms、登录 p95 ≤ 5000ms、配置服务 p95 ≤ 2000ms，零 HTTP/浏览器错误，本次通过。应用首次读取没有清除 PG/系统缓存；配置服务指标不包含后台 UI 点击时间。短测不证明长期稳定性、吞吐上限、第三语言或整套系统的 4 vCPU / 8 GiB 容量。共享登录及外部提供方由其他功能测试验证，不在这里施压外部平台。

完整容量数据加密备份约 2.0 秒，隔离新库恢复约 8.6 秒（还原行数和迁移通过）。该耗时不包含故障发现、异地取回、应用启动、TLS/DNS 与切换；没有据此承诺生产 RTO/RPO。
