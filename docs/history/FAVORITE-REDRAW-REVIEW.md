# 收藏跨重绘操作 Review

日期：2026-10-20。延续 [个人投稿历史分页 Review](SUBMISSION-HISTORY-REVIEW.md)，修复取消收藏与列表重绘、尾页缩减交错时的等待状态及读取归属。沿用原个人接口，不修改服务端业务协议、依赖、正式迁移或旧站。

## 问题与修复

原取消收藏只用按钮自己的 removing 状态。等待 POST 时切换语言或翻投稿页，列表重新生成相同资源的按钮，等待状态随旧 DOM 消失，可以再次发出同一取消请求。

现在个人页维护按 resource_id 归属的 pendingRemovals。新生成按钮继承该资源的等待状态，事件处理也检查同一集合；等待覆盖 POST 及其后续读取。finally 解除该资源状态并同步当前 DOM，而非只恢复旧按钮。不同资源仍可分别取消，一个完成或失败不能提前解锁另一个。这是当前页面的重复操作保护，不是跨标签页或服务端互斥协议。

取消收藏后，原页可能已经超出剩余总数。当前有效读取若返回空列表且页码超过 `max(1,ceil(total/limit))`，会只读载入有效末页；全部为空时回到第一页。投稿页码、表单输入和已确认提示保留。先验证读取代次再纠正，旧空页响应不能回退较新的语言选择。

自动纠正是原读取的延续，沿用原 messageVersion。它可以更新列表，但不能重新取得较新动作的提示归属，清除或替换新的投稿失败信息。手动语言切换、翻页和重试仍采用其发起时的当前归属。

## 验证

新增 7 项浏览器回归：语言重绘后同资源仍锁定及失败解锁、末页删除后剩 24/0 条时的位置恢复、自动纠正不清除新投稿错误、不同资源同时取消的独立锁定、投稿翻页重绘后的等待与成功恢复、旧空页响应不改变新语言。

最初 3 个反例在旧实现全部失败，初步修复后通过；追加自动纠正提示归属反例，在初步修复版复现失败，补齐后共 7 项通过。测试控制 POST/GET 返回顺序，验证按钮状态、请求次数、有效页、投稿页、未提交输入及提示；不把模拟接口的成功响应称为数据库提交证明。已有真实个人 API 与数据库并发回归继续验证服务端授权、限流及收藏写入。

生产构建完成后执行完整 P1/P2/P3/P4 回归 248 项，发行测试 69 项，共 317 项通过；类型与边界检查通过。最终工作区、导出目录和源码归档逐文件摘要以及公开本地链接核对通过。未重验 Docker 安装、容量或真实外部 OAuth。

品牌、真实 OAuth 联调、4 项依赖许可证材料及 7 项镜像材料仍为发行前置项，门禁保持阻断；旧站未修改。
