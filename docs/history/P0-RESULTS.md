## 已验证的技术取舍

- 配置采用共享草稿、版本比较并交换、事务发布与持久化事件；旧版本写入明确拒绝。文件协作为导出、校验、差异预览、显式导入。
- 默认缓存采用版本加短 TTL，进程独立缓存；停站、模块和资源可见性查询权威数据库。数据库失效返回 503，不无限使用旧配置。
- Next.js 动态路由可以承接数据库中的站点、语言与路径变更。配置发布不需要重新部署代码。
- 锁定 Better Auth 1.7.10；按安装源码核对实际授权入口与回调。ID token 验证后读取 userinfo，并检查 subject 一致性。不同域保留各自 Cookie，通过顶层跳转共享身份。
- 中心会话与站点会话显式关联；请求内绑定已验证的中心身份，避免同账号并发登录相互覆盖。中心退出后站点后续受保护请求拒绝；不依赖前端删除其他域 Cookie。

## P0 剩余工作和估算

以下为开发建议，不是新增用户决策。按一位熟悉栈的开发者估算，包含验证，不是承诺工期。

1. 正式身份适配器、共享表和预览会话整合，重跑多域浏览器及权限回归：3–5 人日。认证原型按角色使用表前缀，规范模型另行测试，不能将二者视为已整合。
2. 首次并发 OAuth 身份创建的恢复体验、迁移冲突处理及中断恢复：2–3 人日。当前数据库防重复，但两个首次回调同时创建本地身份时，一个可能失败；须明确可重试结果，不能静默合并。
3. 持久化事件消费重试和进程中断恢复证据：1–2 人日。
4. 来源清单与许可证确认：约 0.5–1 人日整理，权属确认等待时间不计入。内部清单位于被忽略的 `.local/`，直接依赖见 [依赖清单](../DEPENDENCIES.md)。最终许可证未确定。

以上完成并复核退出标准后再进入 P1。容量压测、真实代理部署、备份恢复及完整公开页面按照开发方案后续阶段执行。
