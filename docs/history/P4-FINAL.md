# P4 开源项目目录交付与 Review

日期：2026-10-18。用户确认首个垂直模块为开源项目目录、首个来源为 GitHub。本轮实现该模块并追加 P3 认证修复；P4 的实现、实现者 Review 修复和约定本地验收已完成。

## 实现范围

- 模块声明、配置依赖与按站开关；repository 主档类型、严格 GitHub 元数据、SDK 可选字段及内置模板展示。
- GitHub 来源配置、定时/手动排队、持久限流预算、条件请求、租约认领、重试/终止及接管恢复。
- 按字段人工审核候选，主档版本与审计原子写入；各站发布冻结项目字段，采集和主档更新不直接改变线上。
- 全局运营后台、运行任务汇总、CLI，以及公开数据层一致可见性；普通网站与项目模块分别控制。
- 增量迁移 005；旧迁移不改动，既有网站发布继续兼容。没有新增 npm 运行依赖。

完整操作、接口、默认行为与边界统一见 [P4 GitHub 操作](../P4-GITHUB.md)。

后续管理交互修复见 [GitHub 来源与候选交互 Review](GITHUB-UI-REVIEW.md)，补充写入等待互斥、读取恢复和来源/候选编辑状态保护。

## Review 与修复

1. 两个负面浏览器测试先复现 P3 问题，再修复：旧会话删除 Cookie 不再覆盖新登录 Cookie；只移除被清理的凭据，保留 OAuth state，解决授权期间会话过期后的返回失败。
2. 任务使用来源版本和租约令牌，成功/失败均拒绝旧消费者；模块关闭或来源变更后的在途请求不能落库。
3. 手动请求幂等映射单独持久化，合并到已有任务后，重复同一操作标识仍返回原任务。
4. 游标、候选与任务完成同事务；故障注入验证提交中断全部回滚。审核也原子更新主档版本、历史、审计和候选。
5. 审核显式选择字段，当前版本变化报冲突，保持未选文案/内部备注；新版主档不会自动修改各站覆盖和旧发布快照。
6. 固定 API 地址、超时与大小上限，拒绝跳转/私有响应/仓库身份替换；网络流中断可重试，格式错误终止，安全错误码不含原始响应或令牌。
7. 统一公共视图按站权威门控项目，停用开源模块仍保留普通网站；项目元数据同发布快照冻结。
8. 新增导航导致的手机横向溢出已修复；异步刷新使用代次与路由取消，旧响应不能覆盖新导航或正在审核的材料。

以上为实现者 Review，不是第三方安全审计。AI 生成模板上线的人工审查要求保持不变。
