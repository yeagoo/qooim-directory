## 已实现

### 持久化事件消费

`p0/internal/outbox.ts` 提供原子领取、数据库租约、重试退避、次数上限和终态。多个消费者使用行锁跳过已锁任务；每次领取生成新令牌，过期消费者不能确认或修改新租约。过期的最后一次执行转为 failed，避免无限滞留 processing。

本轮消费者把站点最新已处理修订写入 `config_delivery`，效果和确认在同一事务中完成。使用最大修订号，乱序或重复消费不会倒退。`outbox-process.ts` 是可持续运行的独立进程入口，接收终止信号后结束循环并关闭连接；数据库故障仅记录固定错误信息，避免记录连接凭据或业务内容。

这是本地数据库投影的消费链路，尚未接入邮件、外部搜索或消息服务。外部副作用只能按至少一次交付设计，须由接收端支持幂等键；数据库租约不能撤回已经发出的外部请求。不承诺跨系统恰好一次。

### 规范身份映射入口

`IdentityStore.provisionVerifiedSubject` 在事务内锁定账号空间与站点，以 space + issuer + subject 查找身份，为站点建立默认 reader 成员。并发首次调用复用同一用户，不产生重复身份。既有成员权限保持原值，封禁用户拒绝进入。

邮箱只作为联系字段：不同 subject 使用同一邮箱时返回需要显式关联的冲突，不自动继承已有用户或权限。独立空间仍生成不同用户。发生冲突时整个事务回滚。

该入口仅供可信服务端认证适配层使用，本身不验证 OIDC token，不能作为公开注册接口。调用前必须由认证层验证 issuer、audience、nonce 和 subject。它尚未替换第一轮 Better Auth 角色表中的首次账号创建流程，因此浏览器首次并发注册问题尚不能标记为已解决。

## Review 与修复

| 发现 | 处理 | 证据 |
| --- | --- | --- |
| 发布成功后无人消费持久化事件 | 新增独立执行入口与持久化投影 | 成功消费与投影断言 |
| 消费者崩溃后 processing 永久挂起 | 到期租约可重新领取，最后一次过期进入 failed | 真正 SIGKILL 子进程后，推进数据库租约到期并恢复消费 |

| 副作用成功但确认失败可能导致重复 | 本地效果与确认共用事务，投影按修订单调更新 | 注入约束失败回滚、乱序交付不倒退 |
| 无限制重试可能无限占用资源 | 指数退避、最多次数、明确失败终态 | 到期重试、达到上限与崩溃到上限 |
| 按邮箱合并可能跨身份继承权限 | 仅以已验证 subject 定位；邮箱碰撞显式拒绝 | 并发、跨站、跨空间、邮箱碰撞及封禁测试 |

4. 原型 SQL 为隔离数据库初始化，不是已有部署的增量迁移脚本。上线前须另行实现并演练迁移。
5. 最终许可证、权属确认及后续产品范围仍按原方案处理，旧站群保持原样。
