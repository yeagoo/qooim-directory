# 配置编辑写入与刷新 Review

日期：2026-10-19 至 2026-10-20。承接[事务权限审查](PERMISSION-TRANSACTION-REVIEW.md)，本轮检查后台配置页保存、发布、启停和历史恢复的页面流程，不修改配置协议或服务端业务。

## 发现与修复

四类操作原先写入成功后直接读取并重绘配置页。读取失败会覆盖写入成功提示，并重新启用旧版本按钮；操作之间没有统一等待控制。现在写入与配置刷新互斥，等待期间冻结配置字段及相关按钮，并在处理函数检查状态。明确写入成功后保留对应确认；后续读取失败单独提示，旧写入入口保持禁用，通过只读刷新确认状态，不自动再次提交。

发布操作只发布已保存草稿，启停只改变站点状态，但原先重绘会清掉未提交的本地配置。现在发布、启停和历史恢复在刷新时保留本视图内未保存的 JSON、表单、导入文件元数据及展开状态，明确提示“未保存的编辑已保留”。保存成功则显示新保存的服务器草稿；未作本地编辑时，发布或恢复历史直接展示服务器结果。

“刷新并保留编辑”只读取最新列表与配置版本，同时保留未提交内容。“放弃本页编辑并载入服务器配置”是明确的只读替换入口：成功取得服务器结果后才替换本地内容，优先显示服务端草稿，无草稿时显示线上配置；读取失败仍保留原输入。切换页面或刷新浏览器没有新增草稿持久化，输入不写入 URL、localStorage 或 sessionStorage。

刷新取得新版本后，后续操作使用新读取的 revision/draftVersion；若保留本地编辑时版本已变化，清除旧的替换勾选并提示重新比较确认，防止将旧版本授权用于新共享草稿。版本未变化时保留原确认。导入文件原有 baseRevision、kind、sourceDraftVersion 等元数据保持原样，不因刷新而静默改写基础版本。过期导入仍交由既有服务端校验拒绝。发布失败后的显式重试在同一页面继续复用原 operationId，刷新到新页面后才生成新的操作标识。

读取或校验文件期间仍拒绝写入和页面刷新，避免尚未完成的文件选择被丢弃。比较保持可继续编辑的既有体验；开始写入或读取恢复时使旧比较失效，其迟到结果或结束回调不能重新启用等待中的控件。

补充审查发现，先前发起的导出读取若随后失败，也会覆盖写入成功后的提示。现在这类读取按当前页面操作归属处理，旧操作的错误不会覆盖新写入结果，旧响应也不会在新操作后触发下载。单纯编辑本地内容不会取消已请求的线上配置下载。离开当前视图的请求继续受原作用域限制。

## 验证设计

新增21项 Chromium 浏览器回归。最先13项在旧实现11项失败、2项通过，修复后13项全部通过，既有慢文件/比较回归也通过。后续补充7项用于验证不完整 JSON 的读取恢复与显式替换、迟到比较对等待状态的影响、导入元数据、无本地编辑的发布/历史恢复版本推进、迟到导出失败及编辑期间正常下载。

另对新增读取恢复路径补充版本确认反例，修复前旧勾选仍为true，测试失败；修复后要求勾选失效、输入保留，并验证后续保存使用新版本且replace为false。

前13项覆盖四类操作分别的重复/竞争事件与成功后读取失败恢复（8项），三类非保存操作保留本地编辑（3项），发布被拒绝后输入和 operationId 保留，以及迟到历史恢复响应不覆盖其他页面。

使用真实后台页面/脚本与隔离数据库会话，配置资料和写入结果由受控浏览器路由夹具提供，验证页面流程；不宣称这些夹具重新验证真实持久写入。既有 P1 HTTP/数据库/浏览器回归继续覆盖真实配置版本、建站、发布、权限与准备任务。显式 Promise 控制提交、比较、导出和读取时机，核对实际请求、按钮、输入、版本和下载，没有固定延迟猜测完成时机。
