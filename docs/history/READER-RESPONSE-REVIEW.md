# 读者响应异常恢复 Review

日期：2026-10-20。延续 [目录收藏与共享提示 Review](CATALOG-ACTION-REVIEW.md)，检查公共目录与个人页收到代理错误页、损坏 JSON 和异常错误结构后的提示与恢复。仅修改读者端请求边界，复用现有 API、会话判断、等待状态与消息归属。

## 问题与修复

原公共请求函数先解析 JSON，再判断 HTTP 状态。HTML 401 会变成没有 status 的解析异常，个人页进入临时故障分支，没有登录入口；HTML 503 也会直接显示解析异常。错误 JSON 为 null 时访问 error 抛出异常，error 为对象时又显示“[object Object]”。

现在 JSON 解析失败后仍检查 HTTP 状态。401 始终带原状态和登录提示，个人页给出登录入口；其他错误依次采用非空字符串 error、message，否则给出含 HTTP 状态的通用中文提示。不会把 HTML 错误页或对象错误直接转成用户提示；文本仍通过 textContent 显示。

成功 HTTP 响应如果无法解析为 JSON 对象或数组，不能作为操作确认。GET 提示响应格式异常并保留原只读重试路径；POST 提示结果尚未确认，先刷新记录核对，避免重复提交。退出另行提示刷新页面核对登录状态。不会显示成功、自动导航或自动重放写入。原表单输入保留，等待状态解除；明确的非成功 HTTP 退出仍可按原按钮重试。

这是响应解析和顶层 JSON 容器检查，不是完整的逐字段响应 schema 校验。正常投稿列表数组与其他对象响应仍兼容；不新增接口或承诺代理返回了有效业务响应。网络中断后的服务端提交状态仍应通过已有记录或登录状态核对。

## 验证

新增 8 项浏览器回归：HTML 401 恢复登录入口；HTML 503、null 503、null 200 分别给出稳定提示并只读恢复；结构化 error 不遮蔽字符串 message；201 损坏 JSON 投稿保留全部输入且切换语言只读核对不重放；HTML 502 退出失败后可重试；200 损坏 JSON 退出提示核对登录状态，刷新发现已退出且没有第二个 POST。

最初 7 项在旧实现全部失败，修复后通过；追加退出未确认提示反例在初步修复版失败，补齐后验证全部 8 项。测试使用实际目录/个人页与脚本，控制响应内容和顺序，校验按钮、提示、请求次数、输入及导航；其中退出状态变化为受控会话响应，不作为真实平台退出或数据库提交证据。已有真实 API、授权和会话回归继续保留。
