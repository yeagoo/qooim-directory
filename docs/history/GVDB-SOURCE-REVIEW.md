## 精确输入与原始材料

GLib 2.90.0 原始归档中的 [gvdb.wrap](../../third-party/sources/glib-2.90.0/gvdb.wrap) 指向 GNOME gvdb 的 `2b42fc75f09dbe1cd1057580b5782b08f2dcb400`。打包配方第 149 行包含 `--force-fallback-for=gvdb`。保留的 wrap 继续绑定父 GLib 源 URL、归档 SHA-256 及原始成员名。

从 [GNOME 官方固定提交归档](https://gitlab.gnome.org/GNOME/gvdb/-/archive/2b42fc75f09dbe1cd1057580b5782b08f2dcb400/gvdb-2b42fc75f09dbe1cd1057580b5782b08f2dcb400.tar.gz) 取得 24,716 字节，SHA-256 为 `069a00aa1fc893f18423602f4e095583be5a220429f6e8a58d70511490b4b019`。归档 PAX comment 与该固定提交一致；这只是官方 HTTPS 取得的材料及元数据一致性，不是上游发布者签名验证。浏览工具访问固定树页面返回 406，随后直接读取官方归档成功，没有改用镜像、主分支或最新版本。

[材料索引](../../third-party/gvdb-source/collection.json) 保留归档全部 14 个普通成员，去重后仍为 14 份原始文件、108,451 字节。包括源码、测试、Meson 配置、README、项目元数据、`.gitignore`、COPYING 和 LICENSES/LGPL-2.1-or-later.txt。两个原始许可文件不同，分别保留全文；源码中的原始版权、作者和 SPDX 声明没有改写。没有用通用许可模板代替原文。

所有原始文件按内容摘要放入 `third-party/gvdb-source/texts/`，索引保存原始归档成员名；公开导出不按成员路径展开或执行源代码。原始压缩归档留本地，索引明确 archiveIncluded=false。该材料补齐一项嵌套来源，不等于完整原生包的对应源码交付，也不证明历史二进制包含、签名认证或许可义务全部完成。gvdb 的 Meson 文件通过源文件声明依赖，未据此假设它是独立安装的共享库。

## Review 修复

先新增三条导出回归，旧门禁全部因缺少预期拒绝而失败：即使 gvdb 索引缺失、源文件被改、清单漏项或范围被提升，旧实现仍会接受。现在实际源码导出在工作目录和复制后副本中都验证：

- GLib 必须关联 gvdb 材料索引，索引、维护工具和共享归档检查器摘要相符。
- 父归档身份、wrap 原文、固定仓库/提交/归档 URL、PAX comment 及配方选择行一致。
- 固定提交的 14 项原始成员逐一存在，内容摘要、完整字节数与总计正确；两条通知必须对应其原始完整成员。
- 拒绝分支替换、原文变动、清单漏项、路径越界、符号链接、未绑定索引，以及历史匹配或签名验证的冒认。

维护工具还复现了采集期间输入归档被替换的失败路径：旧实现校验一次摘要后又按原路径打开，可能让源码/通知内容与所记录归档摘要不符。新增测试先得到 6 通过、1 失败，再改为源码读取已校验字节的内存流，共享通知检查读取这些相同字节的私有临时副本。原输入即使随后被替换，本次材料仍来自同一校验快照。临时副本自动清理，不进入公开导出。

只针对已核对的这个固定提交定义 14 项清单，不宣称是任意仓库采集框架。后续更换 GLib/gvdb 提交时须明确 review 新清单。现有共享归档检查器没有修改，避免其他已绑定证据无关漂移。

## 离线维护

新增 [维护工具](../../scripts/collect-gvdb-source.py)，需要 Python 3.11+ 标准库，应用和 Docker 不增加依赖。先只读下载上述官方归档并独立记录摘要，再执行：

```bash
python3 -B scripts/collect-gvdb-source.py third-party/libvips-source-review.json .local/NEW-gvdb.tar.gz 069a00aa1fc893f18423602f4e095583be5a220429f6e8a58d70511490b4b019 .local/NEW-gvdb-evidence
python3 -B -m unittest discover -s tests/p5 -p 'test_*.py'
pnpm test:release
```

采集命令不联网、不执行源码，不调用 Meson、编译器或补丁。原始归档上限 8 MiB，解压成员总量上限 16 MiB，最多 2,000 成员，每个普通文件最多 2 MiB；拒绝不符 checksum、错误提交元数据、穿越、重名、链接、特殊成员及缺失/多出的文件。复用已有通知检查器保留原文。

输出目录必须不存在；失败不写成功 collection.json。若写入过程失败，可保留本次私有目录供排查，不承诺整个目录在磁盘故障或断电时的事务恢复。两次独立输出应逐项比较索引与材料，而不是以再次取得最新版本代替离线复检。
