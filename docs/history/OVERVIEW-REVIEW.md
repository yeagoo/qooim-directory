# 建站与总览流程 Review

日期：2026-10-19。承接[账号与任务控制](ACCOUNT-CONTROL-REVIEW.md)中的建站事务权限审查，本轮检查后台总览与创建站点的页面流程。

## 发现与修复

原先创建成功后调用全局 `load`，重新读取账号和站点列表并渲染路由。该函数会吞掉读取错误，成功时又清掉“站点已创建”的提示；读取较慢时切到成员页填写内容，迟到刷新会重绘成员页并丢失输入。创建按钮也仅依赖通用监听器禁用，没有处理函数中的等待判断，其他字段可继续编辑。

现在总览使用独立内部渲染函数，并沿用原 `scope.current` 和作用域 API。创建后的列表读取留在原视图内，不再调用全局加载函数。POST 确认成功后清空本次创建字段并保留成功提示；列表读取失败单独说明“已创建，但列表刷新失败”，旧创建入口保持禁用，使用新增“刷新列表”只读恢复，不重发创建请求。

创建和手动刷新共用等待状态，字段与相关按钮在等待中禁用，处理函数也拒绝重复触发。创建被拒绝则保留输入并恢复编辑。手动刷新保留当前视图内尚未提交的标识、名称、源地址和账号模式，不写入持久存储。刷新后原共享中心不再出现在列表时，保留原选择并显示重选提示，禁止创建，直到操作者明确选择可用中心或独立模式；不会把账号模式静默改成独立。

初始化原先在站点列表还没返回时就设置 `me`，导航可以提前绘制表单，随后初始化再次绘制导致输入丢失。现在账号和列表都到齐后一次赋值，期间导航只记录目标 hash，完成后显示最新选择的页面。没有重新加载可编辑页面来补充初始化数据。

只读成员同样可刷新其有权看到的列表，页面不新增建站表单。列表资格和客户端等待只用于交互，真实权限、域名及账号中心约束仍由现有服务端判断，没有改变 API、身份或任务策略。

## 验证设计

新增10项 Chromium 浏览器回归：创建等待时冻结输入和拒绝重复事件；创建已成功但列表失败后的只读恢复；成功卡片与确认保留；迟到 POST 和迟到刷新分别不能重置新页面输入；明确拒绝后输入恢复；初始化数据未齐时不提前绘制表单；手动刷新互斥、读取失败恢复及草稿保留；共享中心不再列出时要求明确重选；只读成员刷新。

最先7项在旧实现5项失败、2项通过，修复后7项全部通过；随后补充3项。页面和脚本使用真实后台，后台会话来自隔离数据库，账号资料、站点列表和写入响应由受控浏览器夹具提供，验证页面流程而非新建真实域名或重跑真实账号服务准备。

显式 Promise 控制提交和读取时机，核对请求次数及载荷、字段状态、提示、卡片、未提交内容和导航归属。重复触发包含 DOM 事件，不只依赖原生按钮禁用。既有 P1 HTTP/数据库用例继续验证真实建站权限与准备流程。
