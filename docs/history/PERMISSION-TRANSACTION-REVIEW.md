# 发布与站点状态的事务权限 Review

日期：2026-10-19。范围是配置写入、内容候选保存/发布/下架及站点启停的权限与事务一致性。

## 问题与修复

内容候选保存、发布、下架与站点启停原先在进入事务、等待业务锁前检查运营权限。请求排队期间，站点授权删除、编辑降为只读或账号停用可以提交；旧请求随后取得业务锁仍继续写入。配置写入已在事务中复核并锁账号行，但没有锁站点授权行，授权仍可能在配置提交前被删除。

现在复用 `Operators.require`，允许可信内部调用传入当前事务连接；传入时用共享行锁读取账号与实际需要的站点授权。内容操作与站点状态在取得业务锁后重新复核，配置保存、发布和回滚复用相同检查。账号与授权行保持锁定直到提交或回滚，避免校验与写入之间再次失效。全局管理员仅依赖全局角色，不因无关站点授权变化失去全局权限。

候选首次分发仍要求全局权限，嵌套检查也使用同一事务连接，不在持锁期间另从业务池取连接。外围快速权限检查继续保留，传给服务的角色快照不能替代数据库中的实时权限。

并发顺序明确为：

- 撤权、降权或账号停用先提交：排队写入重新检查后返回403，不改发布、草稿或操作审计。
- 写入先完成事务内授权：撤权等待当前写入提交/回滚；撤权完成后，后续操作被拒绝。

不追溯取消已经提交的业务操作，也不承诺撤权永不等待。站点状态先锁本站记录再复核权限；直接服务调用遇到不存在的站点返回404。

## 验证设计

五项真实 PostgreSQL 并发回归在旧实现均失败，修复后通过，另补配置授权持有回归：

- 用已取得的发布 advisory lock 阻塞候选保存、发布和下架，在等待期间分别删除授权、降为只读、停用账号；释放业务锁后拒绝，并核对发布、草稿与业务审计未变。
- 阻塞站点行，在等待期间撤销编辑授权，释放后不能停站。
- 用仅测试数据库中的触发器阻塞已授权发布，验证撤权真实等待发布事务；释放后发布先提交，撤权生效，后续下架被拒绝。
- 同样阻塞配置草稿更新，验证站点授权持有到事务结束，撤权完成后不能发布配置。

通过 `pg_blocking_pids` 检查实际阻塞关系，不使用固定睡眠推断顺序；所有测试数据库都由隔离运行器校验归属。测试触发器、函数和连接在 finally 清理，不进入正式迁移或生产代码。
