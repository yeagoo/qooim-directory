# 内容双版本接续 Review

日期：2026-10-18。本轮处理内容草稿保存、发布和下架的连续操作，复用现有接口和服务端版本检查。

## 问题与修复

旧编辑保护会丢弃继续输入后的成功回填。草稿从版本1保存到2后，下一次仍提交draft:1。新增浏览器用例在原代码上29项通过、1项失败，捕获旧草稿版本请求。

现在把编辑器基线确认提前到POST成功时。保存草稿采用响应draftVersion及请求中的已知发布版本；发布采用响应发布版本及该请求所消费的草稿版本加1；下架只推进响应确认的发布版本。当前目标身份包含站点视图、资源、语言和选择代次，输入保留与版本接续分别处理。切换目标不回填另一编辑器；当前页缓存记录原目标的本次确认结果，但不回退已观察到的更高发布/草稿版本。

列表刷新只更新发布表和分页，不再从GET结果整行回填编辑器。移除原先等待列表返回的版本接续队列，本次确认基线不会被随后查询到的外部修改自动替换。用户主动重新选择列表中的记录时才采用该记录。外部并发修改仍由服务端双版本检查拒绝。

保存、发布、下架在一次写入及后续列表刷新完成前共用忙碌状态，防止三个按钮交错提交不同基线；文本编辑、选择和只读检查仍可使用。已提交响应与列表刷新失败分别提示；当前目标请求失败保留输入且不推测版本。确认成功后更新发布操作UUID；响应不明时保留原UUID和原基线，允许原样重试。若用户更改目标或参数，应重新载入核对，不能把UUID理解为任意参数的重试许可。

预览和发布仍读取已保存草稿；发布之前已经编辑但未保存、以及请求期间后来输入的文本都保留，仍须另行保存后发布。只修改JSON格式也保守视为本地编辑，保护文本优先。新分发成功后锁定资源和语言，避免随后仍按空基线提交。
