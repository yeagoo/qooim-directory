# 账号响应确认 Review

日期：2026-10-20。延续 [账号页面流程 Review](ACCOUNT-FLOW-REVIEW.md)，修复登录、注册、找回/重置密码及外部登录收到异常响应后的确认与恢复。仅修改账号页客户端，不变更认证 API、限流、账号空间、签名查询或自动/手动流程归属。

## 问题与修复

原 send 先解析 JSON，再检查状态。HTML 错误页、null 错误体会显示解析或属性异常，结构化 message 则变成对象文本。现在解析失败仍检查 HTTP 状态，按非空字符串 message、error 选择原因，否则显示带 HTTP 状态的通用提示；通过 textContent 展示。

原找回、重置和重发验证邮件流程在任意成功 HTTP 响应后展示确认，200 null 或 status:false 也会被当作已受理。现在所有认证结果必须是 JSON 对象，这三类操作还须明确 status:true。该约定已对照本地锁定 Better Auth 1.7.10 的 password 与 email-verification 实现核查。找回与验证邮件仍使用不暴露邮箱是否存在的原确认文案。

外部/共享登录须返回非空 url，自动 OAuth 续接须返回非空 redirect_uri；缺失时不跳转 undefined。邮箱登录须有非空 token 或 url；注册还接受 token:null 且 user.id 非空的待验证结果。没有把邮箱登录一律限制为 token/user，因为 OAuth Provider 的 after hook 会把授权流程改写为带 url 的跳转结果，该形式已核对本地 handleRedirect 实现。以上是客户端使用的必要确认字段检查，不是完整响应 schema，也没有更改服务端跳转地址校验和信任策略。

无法确认的成功响应不显示成功或继续跳转，而是提示先核对邮件或登录状态，避免重复提交。原输入与密码重置 token 保留；只有明确重置成功才从地址栏移除 token。原 busy 守卫、按钮恢复和自动续接不得覆盖手动操作的规则保留，不自动重放请求。若实际重置已成功，服务端仍按原规则拒绝再次使用 token；前端保留它不代表可以重复使用。

## 验证
