# 会话绝对有效期一致性 Review

日期：2026-10-19。本轮检查会话生命周期在共用服务、正式认证和原型预览之间的一致性。

## 影响与修复

正式 `AuthRegistry` 和个人业务写入层已检查 `absolute_expires_at`，共用 `IdentityStore.authorize` 与 `revokeGroup` 却只检查普通 `expires_at`。因此，当普通有效期仍未到但绝对期限已过时，共用服务仍可能授权，过期来源会话仍可触发同组退出；使用这层授权的原型预览也受影响。

正式应用路由没有使用原型的 Bearer 会话预览入口，正式登录与共享登录已经检查绝对期限。本轮不将此问题描述为正式登录入口的到期绕过。

现将授权与组退出来源的 SQL 判断补齐为两种期限均须有效，保留站点、身份空间、角色、封禁和原有组退出范围。直接在同一 SQL 判断时效，没有先查后写的时间差，也没有恢复或延长任何已过期会话。

生产迁移 004 已有该字段，正式迁移不变。仅给原型数据库夹具补同名非空字段及 30 天默认值，使原型回归使用共用服务时遵守同一到期约束；不在生产代码中兼容缺失字段或跳过校验。

## 验证设计

- 两项身份回归：普通期限有效而绝对期限已过时拒绝授权；绝对到期的来源不能撤销同组另一条会话。修复前原有 9 项通过，新增两项均失败，修复后验证。
- 原型真实 HTTP 预览：先验证编辑权限可预览，再仅将绝对期限改为过去，返回 404；恢复期限后继续验证权限降级。与匿名、跨站、草稿语言和 no-store 检查同用一个实际服务。
- 正式 P3 会话测试：同一真实登录会话在绝对到期前共用服务允许访问，到期后共用服务拒绝，同时保留共享站点与正式 OAuth 入口已有的到期检查。

本轮不涉及新依赖、配置格式或数据迁移。
