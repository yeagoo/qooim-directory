## Review 修复

先新增三条回归，旧门禁均因缺少预期拒绝而失败，确认补丁材料未被实际检查。现在工作目录及导出副本均执行相同校验：

- 配方须是已有摘要校验的资产；存在正式 build-posix.sh 时，不能将补丁清单改绑到无关文件。
- 配方中的下载补丁命令与索引一一对应，行号和 URL 相同；漏项、重复项和不支持的命令格式拒绝导出。
- 补丁须位于指定内容摘要路径，且为无符号链接的普通文件；沿用证据文件 2 MiB 上限，校验原文摘要和字节数。
- 下载状态、固定引用标记及历史范围必须符合记录，拒绝把可变 PR 引用标为不可变或把历史匹配升为 verified。

这是针对当前精确配方的检查器，只支持其中的 `$CURL URL | patch -p1` 格式；上游改写格式时应明确更新并复核检查器。它不解析任意 shell 控制流，也不是补丁执行沙箱。摘要用于发现证据与所记录输入不一致，不替代可信发布者认证或人工审查。
