# 后台任务页 Review

日期：2026-10-19。承接[账号与任务控制](ACCOUNT-CONTROL-REVIEW.md)的服务端状态和事务权限修复，本轮检查后台运行任务页面。

## 发现与修复

任务页原先为 ready、pending、provisioning、failed 都提供认证重试按钮；前一轮服务端已仅接受 failed，其他状态点击会返回409。页面现在仅为失败实例提供重试，仍由服务端最终判断状态和权限。

两种重试原先没有等待控制，连续点击会发送多个请求。页面现在共用等待状态，同一次任务视图内提交重试或刷新列表期间禁用相关按钮，并在处理函数检查等待状态。不同任务的操作同样串行，防止并行刷新覆盖状态。导航仍可切换，沿用既有视图作用域校验，不取消已提交的服务端任务。

重试成功后自动读取列表若失败，原实现只显示读取错误，旧按钮还可操作。现在明确保留已重新排队的结果，说明列表刷新失败；旧操作按钮保持禁用，提供“刷新列表”只读恢复入口。刷新确认新状态后重新绘制资格，没有自动再次提交重试。重试本身被拒绝时显示原错误并解除等待，供操作者在确认权限和状态后重试。

手动刷新期间同样不允许重复刷新或重试；读取失败可再次刷新。迟到的重试/读取响应继续遵守原视图作用域，不覆盖切换后的页面。

## 验证设计

新增8项真实 Chromium 浏览器用例，页面和脚本来自实际后台，身份通过测试隔离库创建的后台会话；列表和重试接口由受控夹具响应，验证的是页面状态流程，不宣称真实 worker 执行。

最先7项在旧实现5项失败、2项通过，修复后全部通过：失败状态资格；认证重试与配置事件重试各自的重复/并行操作防护；两类提交已成功但刷新失败的确认与只读恢复；明确拒绝后可重试；切换视图后的迟到成功。另追加手动刷新互斥与读取失败恢复。

夹具用显式 Promise 控制响应时机；重复点击包括程序触发，以确认等待判断不只依赖视觉禁用。检查实际请求次数、按钮状态、提示和导航归属，没有用固定延迟猜测请求是否完成。正常的服务端权限/状态限制仍由既有 P1 数据库与 HTTP 回归覆盖。
