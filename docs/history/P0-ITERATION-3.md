# P0 第三轮：浏览器身份与权限贯通

历史记录：当前 P0 状态以 [最终验收](P0-FINAL.md) 为准，以下保留当轮发现与限制。

后续结果及迁移范围纠正见 [第四轮进度](P0-ITERATION-4.md)。本文保留执行时的记录。

日期：2026-10-18。状态：已把第二轮规范身份入口接入真实浏览器认证原型；仍是隔离测试夹具，不是可部署的正式认证服务。

## 本轮实现

- A、B、C 共享空间登录后返回相同的规范用户 UUID；独立站 D 保持不同身份。认证库本地用户 ID 不再作为产品身份输出。
- 会话创建钩子将认证库会话关联到 `identity_session`。规范会话和关联记录以同一条数据库语句写入，关联失败时产品入口不放行。
- 产品会话读取查询站点、规范用户、站点成员及会话状态。共享站额外检查中心会话是否仍有效。数据库读取失败返回 503。
- 浏览器 `/preview` 使用真实 Cookie 解析出的规范会话调用公共数据访问层；默认 reader 无权预览，只有本站 editor 可以查看草稿。响应保持 `no-store`，跨站角色不继承。
- 退出时在认证库删除会话之前撤销规范会话；中心退出同时撤销同一中心会话对应的共享站会话，不撤销另一个设备的独立登录。

## 首次并发登录修复

第一轮测试提前建立本地用户，未覆盖首次回调竞争；本轮删除该准备步骤，两次真实浏览器回调同时首次创建本地账号。

在锁定版本的认证库完成 ID token 验证并读取 userinfo 后，以站点、issuer、subject 为键取得 PostgreSQL 事务级 advisory lock，保持到认证库完成回调。第二个请求在第一个请求完成本地账号创建后继续，避免认证库两个首次创建流程相互冲突。整个流程仍由库验证授权码、nonce、PKCE 与回调地址；没有自行跳过 token 验证。

锁连接使用单独、限流的连接池，防止等待回调耗尽业务查询连接。锁等待设置超时，finally 回滚锁事务并释放连接。锁不是跨系统事务，不承诺认证库写入与规范身份写入完全原子；未建立完整桥接记录的本地会话不能访问产品入口。

## Review 发现与处理

| 问题 | 修复 | 验证 |
| --- | --- | --- |
| 共享站输出不同本地用户 ID | 产品统一输出规范 UUID | 三浏览器断言 A/B/C 一致、D 独立 |
| 首次并发回调重复创建本地账号 | 数据库锁覆盖首次身份创建流程 | 两个首次登录及四个浏览器上下文突发登录 |
| 等待锁占用业务连接导致连接饥饿 | 单独的限流锁连接池 | 并发登录完成且未残留 advisory lock |
| 预览授权仅验证人工构造会话 | 浏览器 Cookie → 规范会话 → 数据访问层 | 默认拒绝、授予本站 editor 后通过、撤销后即时拒绝 |
| 本地会话仍可能绕过规范封禁和撤销 | 产品入口权威查询规范身份和会话 | A/B/C 封禁拒绝、单站撤销不影响其他站、缺表返回 503 |
| 认证库退出未撤销规范会话 | 删除前钩子同步撤销，中心按关联范围撤销 | 浏览器退出和规范会话数据库断言 |

这是实现者自查与自动化回归，未进行独立安全审计。

## 仍需完成

1. 认证库依然使用固定角色的前缀表；正式共享表适配器、动态新增认证站点及版本升级迁移尚未实现。不能把本轮浏览器贯通等同于正式适配器交付。
2. 账号迁移仍只有冲突演练，完整迁移执行、审计和中断恢复未实现。
3. 认证库与规范表不是同一个事务；需补持久化对账和孤立会话清理。当前策略是缺失关联拒绝访问；规范会话不会因库会话自动续期而延长，达到较短有效期需重新登录。
4. `/api/auth` 是协议入口，产品授权必须经过规范身份查询。测试夹具不包含完整后台 RBAC、生产限流、正式邮件服务或反向代理配置。
5. 许可证与权属确认仍按原方案处理。旧站群没有改动或迁移。

下一步优先处理正式适配器生命周期与迁移恢复，再复核 P0 退出条件。暂不进入 P1 产品开发。
