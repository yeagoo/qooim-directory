# 后台审计日志 Review

日期：2026-10-20。本轮把既有 `audit_event` 记录接成只读后台能力，不新增审计写入点、不改保留策略、不导出到外部系统。目标是运营和排障时能按站点查看谁在何时做了什么，而不是把审计表当作完整合规系统。

## 交付

- 新增 [audit.ts](../../src/server/audit.ts)：只读查询服务。
- 新增 `GET /admin/api/audit?site=&before=&limit=`：
  - 全局运营管理员不传 `site` 时可查看全部站点事件；
  - 站点 viewer/editor 必须传已授权站点，且只能看到该站事件；
  - 未授权站点、越权全量查询返回 403；未知站点返回 404；
  - `limit` 1–100，默认 50；`before` 为上一页最后一条 id，按 id 倒序游标分页。
- 后台新增“审计日志”入口（`/admin#audit`）：
  - 站点筛选、刷新、加载更多；
  - 显示时间、操作者邮箱、站点、操作中文名/原始 action、detail JSON；
  - 共享站和独立站使用同一入口，按当前账号权限显示可选项。
- 查询返回字段：`id`、`action`、`site_id`、`detail`、`created_at`、`actor_email`。不返回密码、密钥、sealed config 或认证 token。

## 权限边界

| 角色 | 不传 site | 传已授权 site | 传未授权 site |
| --- | --- | --- | --- |
| 全局运营管理员 | 全部事件 | 该站事件 | 该站事件（全局权限） |
| 站点 viewer/editor | 403 | 该站事件 | 403 |

`audit_event.site_id` 为空的事件是全局操作（例如创建成员、停用成员），只在全局视图出现；站点视图不会把全局事件混入站点历史。

## 数据边界

- 审计记录仍是普通 PostgreSQL 表，数据库管理员可直接修改或删除；本轮不宣称防篡改、WORM 或外部留痕。
- `detail` 只做 JSON 序列化和转义，不额外脱敏。现有写入点保存的是 id、版本、角色、locale 等标识，不含密钥；以后新增写入点必须继续遵守这一点。
- 不提供 CSV/JSON 导出、保留期配置、全文检索或告警。需要这些能力时应单独立项并补充权限、脱敏和保留策略。
- 日志量大时按 id 游标分页，不使用 offset；本轮未做归档表或分区。

## 验证

- `tests/p1/platform.test.ts` 新增权限与分页测试：全局管理员可读、站点 viewer 只能读授权站、越权 403、未知站点 404、非法 limit 拒绝。
- `pnpm check`、`pnpm build` 通过。
- 完整 P1 浏览器套件需要免密 sudo 起 Docker 和改 hosts；当前环境未执行，新增 UI 入口需在维护者本机跑 `pnpm test:p1` 复核。

## 未覆盖

- 没有新增 audit_event 写入点，也没有回填历史事件。
- 没有把审计日志暴露给公开站点或非后台成员。
- 没有实现“操作者已删除”后的匿名化；当前通过 `LEFT JOIN` 显示空操作者。
- 没有验证 10 万级 audit_event 的查询性能；当前按主键倒序与 site_id 过滤，索引是否足够需在容量测试中确认。
