# 内容文件协作 Review

日期：2026-10-18。范围为现有资源导入导出及后台文件操作，继续复用资源主档服务、权限与 schemaVersion 1。没有增加数据库迁移、依赖、导入协议版本或上传上限，没有修改旧站。

## 发现及修复

1. **合法导出不能从后台导回**：导出页最多100条，每条允许中英长描述。以24条合法资源复现：完整格式化文件超过256KiB，直接经实际HTTP dry-run返回413。后台导出改为按UTF-8体积拆成多个有效原格式文件，每份同时满足格式化文件、带bundle/apply封装的请求及100条限制；条目保持顺序，不遗漏。单文件继续直接下载，多文件展示逐份下载按钮，避免依赖浏览器连续自动下载权限。原始导出API和CLI不改变结构。
2. **旧文件覆盖新选择**：原先异步File.text完成后无代次核对；清空选择也会留下之前的bundle。现在每次change立即清空内存内容及检查结果，采用选择代次和当前输入节点核对。错误读取和离开页面后的结果也不得重新装载旧内容。
3. **检查请求迟到**：文件重新选择后，旧检查结果或错误提示不能覆盖当前文件状态。已提交的导入事务仍执行，但旧视图的迟到回调不再重绘新选择；未提交的旧文件不会被再次导入。导入完成后的列表保留原搜索和页码。
4. **文件与请求大小差异**：手工编辑文件的体积刚好合规，也可能因为JSON封装超过HTTP上限；载入时额外核对实际请求UTF-8字节数，超限明确提示拆分。

操作协议唯一说明见 [内容文件与CLI](../P2-CONTENT.md)。每份导入继续整体版本检查、单事务回滚并保留本地内部备注；多份分别导入，不能声称整页跨文件原子回滚。更换文件不撤销已提交的写操作。
