## 构建范围修正

精确 [打包配方](../../third-party/sources/sharp-libvips-ebb95f8/build-posix.sh) 在修改 image/cairo 特性之后，第 343 行执行 `cargo update --workspace`，配方注释也说明要重新生成锁文件。此前取得的 Cargo.lock 是源归档原始版本，不能据此宣称已取得构建当时最终使用的锁文件。

按 [Cargo 官方选项说明](https://doc.rust-lang.org/cargo/commands/cargo-update.html#options)，--workspace 尝试仅更新工作区包，其他包只在原锁文件中不存在时更新。因此不能推断所有 357 个注册表包都被升级。我们没有执行该历史构建，没有确认锁文件具体差异或精确目标/特性的实际编译图。

采集记录新增 buildLockStatus，固定为 original-before-recipe-cargo-update-workspace，并绑定原始配方的摘要、大小、命令和行号。导出检查会拒绝 final-build-verified 等范围冒认、错误命令行、配方变更或脱离既有来源资产的记录。本轮为这项明确范围新增失败回归；以前已声明“非编译图”的边界继续保留，没有把新增字段测试当作旧版存在安全漏洞的证明。这项补强不改变原始归档 checksum 的有效性。

本轮没有改变应用依赖、业务数据库或既有站点行为。新增维护流程需要 Python 3.11+，应用运行和 Docker 构建仍不依赖 Python。
