# 读者收藏与投稿页面 Review

日期：2026-10-19。范围是 `/me` 的列表交错、失败恢复和投稿确认，没有改变后台发布或公开可见性规则。

## 问题与修复

旧实现未标记列表请求归属。快速切换语言时，旧成功响应能覆盖新语言，迟到错误能把已经成功加载的收藏替换成登录链接；分页按钮使用可变的当前页，重复点击也可能跳页。所有列表失败均被当作需要登录，网络或服务暂时故障无法就地重试。

现在每次加载固定页码和请求序号，只有最新请求可以更新列表、分页和错误提示。开始加载时清除旧列表及控件，旧控件的回调另有序号检查；语言切换回第一页。临时失败提供重新加载，HTTP 401 才显示登录链接；成功重试清除旧提示与空通知样式，不展示上一轮的投稿列表。

旧实现收到投稿成功响应后直接 reset，丢弃了等待期间继续输入的内容。现在记录表单编辑版本，只有没有后续编辑或语言切换时才 reset。保留等待中的编辑，并提示“当前编辑尚未提交”，包括等待列表刷新期间产生的编辑；未继续编辑的正常成功提交仍清空表单。取消收藏等待期间也禁用当前按钮。

已收到投稿成功响应、但后续读取列表失败时，明确提示“投稿已提交，列表刷新失败”；重新加载只执行 GET，不重复 POST。取消收藏与列表刷新失败也分别提示。没有新增服务器接口、修改提交限额或承诺网络中断下的投稿幂等性。

## 验证方式

五项浏览器故障回归在旧实现全部失败，修复后通过，另补一项分页重复点击检查：

- 中文响应被阻塞，切到英文成功后再释放旧响应；分别验证旧成功和旧 503 均不能覆盖新列表或提示。
- 当前 503 提供重试而非登录；重试成功后清除错误，随后 401 才提供登录。
- 阻塞投稿确认，期间继续输入；确认后保留新内容。
- 已确认投稿后让列表刷新失败，验证明确区分结果；恢复读取后点击重试，POST 总数仍为一次。
- 对同一旧分页按钮重复触发点击，保持在相邻页，不跳过一页。

新增交互测试使用实际页面生成器与页面脚本，用 API 夹具控制顺序和故障；不将这些夹具视为真实登录或服务器持久化验收。完整 P2 回归另验证真实 HTTPS 登录、按站收藏与投稿、审核创建草稿、显式发布和公开可见性规则。
