# 后台导航与配置载入 Review

日期：2026-10-18。范围是现有统一运营后台的页面生命周期与配置文件载入；保持当前路由、服务接口、数据库与依赖不变。

## 问题与修复

- 旧资源页请求延迟返回后可以覆盖已打开的成员页。新增真实Chromium用例在未修复代码上失败：成员输入实际数量0，预期1；原P1十二项仍通过。通用路由原先只对GitHub执行专有取消，其他页面没有统一失效检查。
- 现在每次导航创建路由代次及hash作用域；API发起前、完成后和错误路径均检查有效性。站点配置、成员、任务和资源/内容/GitHub页面统一使用作用域API与消息。旧页面不能继续请求、重新绘制、显示迟到提示或解除新页面加载状态。导航加载期间工作区inert并标记aria-busy，工作区外导航仍可用；已改变hash但导航事件尚未处理时，也不能由旧控件再发起操作。
- 已提交的写事务不会因切换页面被撤销。以真实配置保存已经提交、故意扣留响应为例：切到资源页后释放保存响应，不会跳回配置页；后端草稿确实已经保存。前端失效保护不能替代服务端权限、版本冲突或事务约束。
- 当前页面加载失败时显示错误和重新载入按钮，并释放加载状态；重试重新读取服务端，成功后不残留上次错误提示。旧页面的失败不显示此错误页，也不能解锁当前仍在等待的页面。
- 配置文件读取及服务端compare同样按选择代次和当前编辑节点核对。新文件、手工表单或JSON编辑会使旧载入失效；文件仍在读取/校验时，保存和手动比较明确拒绝使用旧内容。清空选择保留已经装入编辑器的内容和原快照元数据，不把历史baseRevision改成当前版本；只有未完成的文件载入被取消。
- 修改配置或更换文件会清空旧差异；手动比较完成时也重查编辑代次，不把旧差异和校验提示套到新内容上。手动比较属于只读检查，不修改后端草稿。

这里只处理跨路由生命周期及配置文件载入交错，不宣称取消服务端事务或实现跨页面自动保存。后台编辑的版本与发布协议继续见 [配置协议](../CONFIGURATION.md)，资源文件协作规则见 [内容文件Review](CONTENT-EXCHANGE-REVIEW.md)。
