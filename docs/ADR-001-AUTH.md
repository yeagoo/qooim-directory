# ADR-001：P0 认证适配结论

日期：2026-10-18。状态：P0 实施决策，已由实现者 review 并经原型回归验证。并非第三方安全审计或新的用户业务决策。

## 决策

采用锁定版本 Better Auth 1.7.10 与 OAuth Provider 1.7.10，保留独立的认证存储边界；产品身份与权限统一落在规范业务表，通过服务端会话桥接关联。共享 PostgreSQL 不要求所有认证实例共享同一组认证库表。

P0 已验证的适配方式是每个认证实例使用固定前缀表、固定 baseURL/issuer/回调与 Host-only Cookie。账号中心承担共享身份；依赖站只接受该中心验证后的 issuer + subject，业务接口返回统一用户 UUID。独立空间同邮箱不会自动合并。拒绝未经验证的跨空间身份映射。

不在 P0 另外编写通用的 Better Auth 共享表多租户数据库适配器。该方案此前未实现，且不是原定 P0 退出条件；不能把它记为已交付。当前经过验证的存储隔离加规范身份桥接作为产品化基线。P1/P3 若更换数据库适配方式，须重新通过 A01–A11 与所有并发、撤销、故障测试。

## 已验证依据

- 四个不同主域 HTTPS，Chromium、Firefox、WebKit 的真实授权码流程；稳定映射与混合账号空间。
- 库验证 ID token/JWKS、nonce、授权码及 PKCE；自定义 userinfo 检查 sub 一致性。实现按安装源码核对，没有自写 token 验证器。
- PostgreSQL 事务锁保护首次本地账号创建；锁连接池与业务连接池隔离，控制并发与等待时间。
- 浏览器 Cookie → 认证库会话 → 规范会话 → 本站角色 → 预览数据的完整链路。
- 实时权威鉴权与批量对账复用同一有效性查询；中心、本地规范会话撤销都不能被残留认证库会话绕过。
- 认证库和规范模型不能原子提交时，缺少桥接即拒绝产品访问；维护任务撤销、清理孤立状态，不自动重建身份。

测试和边界详见 [P0 最终验收](P0-FINAL.md)。

## 生命周期约束

产品鉴权不得直接使用认证库 get-session 结果。数据库无法确认授权时拒绝访问。服务端模板也不能访问认证内部数据。认证库协议接口不等于产品业务权限入口。

会话有效期取认证库、规范会话、共享中心关联的较短期限。P0 原型不自动延长规范会话；P3 增加受绝对上限约束的续期，详见 [P3 认证操作](P3-AUTH.md)。本站退出只撤销本站会话；中心退出撤销对应中心会话关联的站点会话，不默认退出其他设备。

对账以至少一次执行设计；重复执行无权限副作用。P0 不自动物理清除规范历史与桥接；P3 已增加可配置保留周期和批量清理，详见认证操作。清理任务不承担恢复密码、重建外部绑定或迁移账号的职责。

## 产品化工作归属

| 阶段 | 状态及工作 |
| --- | --- |
| P1 | 已实现受控注册、加密持久密钥与 issuer、可重复建表升级、任务调度和权限、共享连接预算；见 [P1 交付](P1-FINAL.md) |
| P3 | 正式认证界面、邮件服务、生产限流、Cookie/代理配置回归、续期与历史保留策略、外部 OAuth 联调及安全审查 |
| P5 | 安装升级、备份恢复、30 站容量基线和公开发布检查 |

前缀表数量随认证实例增加，不能据四站测试宣称 30 站容量通过。动态公开路由已验证，但P1 已补上受控动态认证实例注册。新站账号模式由客户选择的产品目标保持不变。
